# G1-11 并行 CI 实施记录

> 日期：2026-07-20　状态：已实现，待独立审计；不代表 G1-11 已最终完成。

## 范围

- 新增 8 个职责独立的本地/远程同名作业与最多 4 路本地并行 runner。
- 新增只读权限、固定 Action SHA、冻结安装和锁文件/运行时缓存键的 GitHub Actions workflow。
- 新增高置信度密钥扫描与实际安装依赖许可证扫描；缺失/未知许可、GPL/AGPL fail-closed，已识别但待裁定许可不冒充批准。
- 关闭 IA-01 的测试覆盖缺口：冻结品牌复制、错误层级两个反例进入单元测试。
- 三环境构建使用独立输出目录；不加入空的 render/integration/E2E 命令冒充绿色。

## 明确未完成

- workflow 尚未推送到私有远程，未触发 GitHub Actions；远程首次运行需业主另行授权。
- G1-15 的 SBOM、漏洞分析、依赖用途和特殊许可证裁定不在本任务。
- 当前没有真实数据库、渲染或 E2E 用例，因此 CI 不声称这些层已通过。
- 本记录是实施者自检，不关闭 IA-01，也不替代 Claude 独立审计。

## 关键反例

- 并行首轮中 `static` 因 4 个未格式化文件失败，其他 7 项继续完成，最终汇总精确标记失败；格式化后才允许重跑。
- 许可证扫描初版只报告 11 个工作区路径且许可分布为空，被判为假阳性并废弃；现直接枚举 pnpm 虚拟仓库，覆盖 scoped/unscoped 包并输出非空分布。
- 新文件暂存后，秘密扫描命中测试源码中的私钥头 fixture；fixture 改为运行时分段拼接，保留检测行为且不让仓库自身携带连续敏感形态。
- `tools/ci` 从包目录运行时，workflow 测试因假设 cwd 为仓库根而 `ENOENT`；改为从 `import.meta.url` 解析仓库文件后，根目录与包目录均通过。
- workflow 契约测试要求全部本地作业名进入 matrix、冻结安装、只读权限且 Action 不得使用可移动标签。

最终命令、计数和破坏性验证结果在提交前补入独立审计任务书，供审计者从反例复核，不采信本记录自述。
