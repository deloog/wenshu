## 3. 开工前必须先裁定并回报的三件事

### D1　缺失设计稿的处置（业主动作，且是路线图停止条件）

[决策 #1](../../决策记录.md) 记载「UI 设计稿（版本 `a566a20`）已采用"文枢"品牌呈现」。核查结果：**`a566a20` 不是本仓的 Git 对象**（`git cat-file -t` 不存在），应为外部设计工具的版本号。

路线图对此给的是硬约束——「找回旧稿或正式废弃，**不猜其内容**」。二选一，且**只有业主能做**：

1. **找回**：在设计工具/备份中定位 `a566a20`，导出归档进仓；或登记其不可迁移的存放位置与访问方式；
2. **正式废弃**：在[决策记录](../../决策记录.md)追加一条决策，声明该稿作废、Alpha 视觉从 UX 基线重新导出，并说明品牌呈现的承接方式。

**D1 落定前，A-01 不得产出任何"看起来像设计稿"的东西**——那正是停止条件所禁的"猜其内容"。

### D2　"可验收原型"的形态（决定本棒是文档任务还是首个 UI 实现任务）

路线图未定义"原型"。须书面裁定：

- 是静态图/线框，还是**可运行的 `apps/web` 最小入口**？
- 状态机是否做成**版本化契约**（JSON schema + 校验 + 生成物漂移检查），像 `document-model` / `host-contract` 那样可机械校验、可被 12 个下游 import？

**起草者建议（供裁定，不替业主决定）**：状态机做成 **L0 契约 + 最小可运行原型**。理由：消费者有 12 个，散文描述必然分叉；本仓已多次证明"契约先行 + 门禁机械校验"能防住这类分叉（`G1-04`/`G1-06`/`G2-04` 皆是先例）。

**该裁定直接决定以下两条，请一并回报**：

1. 若原型可运行 → `apps/web` **首次承载真实产品代码**，则 [G2-03 MI-03](G2-03-followups.md) 的**最迟关闭点就在本棒**（原文："`apps/web` 承载生产代码之前"）：`apps/web/vite.config.ts` 等包根配置文件的分层规则集归属须书面裁定并给出反例，**不得以"配置文件不发布"作为免检理由**。
2. `apps/web` 属 **web 层**，只能依赖 L0/L1，**禁 `node:*` / `electron` / `@ohos`**；平台能力一律经 `0.2.0` Host 协议。已知护栏缺口：`apps/web/tsconfig.json:5` 仍声明 `types: ["node"]`，而分层门禁只看 import 不看全局，`Buffer`/`process` 可无 import 穿透（`PB-10` 审计 NOTE）。真实产品代码进场是收口这条的合适时机。

### D3　与 DEGRADE 的接口：分页/预览状态必须按增量分页建模

[ADR-0014](../adr/0014-增量分页可行性与DEGRADE口径.md) 把**增量分页登记为 PB/Alpha 待建架构要求**；[ux-spec §4](../ux-spec.md) 已写"分页中：当前阶段和可取消；**旧预览保留到新结果可用**"。冻结状态机时：

- **不得把"全量重新分页"写死进状态机**——那是 `PA-13` 实测 p95 24.300s / 预算 8s `not_met` 的那条路径；
- 预览状态须能表达"部分页已更新、旧预览仍有效"；
- 本棒不实现分页，但冻结的状态定义**要给 A-04 留出增量的位置**。

## 4. 硬边界（越界即停）

1. **不猜设计稿内容**（路线图停止条件，见 D1）。
2. **不越 UX 基线上限**：[ux-spec §3](../ux-spec.md) 的 **8 项**信息架构是上限，明确排除知识图谱视图、模板市场、自动同步、多端协同、复杂表格、PPT。新想法进[需求池](../requirements-pool.md)，不进 A-01。
3. **不做完整设计系统**（路线图范围外原文）。
4. **无障碍不是 A-13 才开始**：[accessibility.md](../accessibility.md) 的键盘可达、焦点可见、状态有文本等价表达、错误与进度不只依赖颜色，须在**状态机层面**就成立——A-13 是验证，不是补救。
5. **状态不得说谎**：ux-spec §4 每行都含"不得"语义（不出现无意义空白编辑器、不整体吞掉结果、未接受不改正式内容、失败不假装已保存、不循环弹窗）。这些是验收点，不是修辞。
6. 分层与体量护栏照常；**新建 workspace 须先停止上报业主**，不得自行修改业主冻结的分层归属表。

## 5. 验收标准与最低证据（含来源标注）

### 5.1 状态矩阵逐行覆盖 —— 两条来源须分别写明

[ux-spec §4](../ux-spec.md) 的核心状态矩阵共 **12 行**，表头为「场景 | **必须呈现**」。这 12 行中：

| 分组 | 行 | 强制力来源 |
|---|---|---|
| 直接对应路线图完成证据的 6 类 | 导入中、AI 处理中、分页中（加载/取消）；导入部分成功（部分成功）；保存失败、权限拒绝（失败）；离线/模型不可用（离线）；崩溃恢复（恢复） | **路线图 A-01 完成证据**原文 |
| 其余 5 行 | 初次/空项目、AI 结果、页面有问题、导出前、保存成功 | **ux-spec §4「必须呈现」**（经路线图"只含 UX 基线上限"并入） |

**验收：12 行逐行有可验收原型，逐行可对账。** 交付物须对每一行标出其强制力来源属上表哪一组——**不得把两类来源含糊成一句**，也不得以"典型状态已覆盖"替代逐行。

### 5.2 其余验收点

| 验收点 | 最低证据 |
|---|---|
| 信息架构 = ux-spec §3 上限 | 8 项逐项映射；6 类排除项显式列出未纳入 |
| 崩溃恢复状态 | 能表达"恢复到哪个检查点 / 可能丢失什么 / 是否另存恢复副本"——`PB-10`/`PB-12` 已实测的恢复语义要能被 UI 表达 |
| 权限拒绝状态 | 对应 `PB-10` 的 `HOST_PERMISSION_DENIED` + 显式降级枚举；不循环弹窗 |
| 离线/模型不可用 | 本地编辑、排版、检查、导出继续可用；AI 降级有解释（A-07P 才实现，本棒只冻结状态） |
| 若状态机做成契约（D2） | schema + 校验 + 生成物漂移检查接入 `pnpm verify`；**非法状态转移有反例测试** |
| 决定性守卫 | 凡可机械校验的部分，变异它 → 对应测试**因正确原因**变红（DoD §2） |

## 9. 独立审计的猎杀方向（预告）

- **12 行是否逐行有可验收原型**——"典型状态已覆盖"是最可能的偷工形态；
- **是否越了 ux-spec §3 的 8 项上限**；
- **设计稿是否被"猜"出来了**（对照 D1 留痕）；
- **状态机是否把全量分页写死**（D3）；
- **a11y 是否被推给 A-13**；
- 若做成契约：**变异守卫是否决定性**、非法状态转移是否真被拒；
- **承接项是否越权关闭**（§6 两类归属不得混同）。

冻结类任务的典型失败是"写得漂亮但下游各自解读"——审计时会以 12 个消费者的视角逐个去读。
