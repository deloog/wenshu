### 2.4 一个必须记下的口径收窄

第一轮核查另报出 §10 矩阵与任务自述的归属不一致共 **64 处**（正向 16、反向 48，其中 14 处落在 §10 的两个散文兜底格"各任务测试""全部任务的范围外约束"）。

**本任务不修这 64 处，理由须记录在案而非静默略过**：

- §10 末尾的反向规则，其实际目的是"任何任务都必须有已批准的要求来源"——这一点由**检查 3 完整覆盖**，且当前 0 违反。
- 而"某任务算不算某需求的实现者"是**编辑判断**（主责 / 贡献性参与），路线图从未定义过口径。要求双向一致就是要求逐条裁定 64 处归属，其中大量落在已签署任务行的 `R-*` 标注上。
- 为满足一条从未声明的一致性要求而制造 64 处编辑，不成比例，且会动到已签署证据。

**裁定：§10 明确声明为编辑性覆盖摘要，不是派生索引。**该声明须写入 §10 本文，避免将来又被当成可校验对象。相应地，检查 6 只校验其引用的任务 ID 存在。

## 3. 手写真源与被校验对象的划分

**唯一手写真源（三项）**

1. §4~§8 任务表的**依赖列**（直接依赖，语义须写入路线图本文）
2. 任务的 `R-*` 标注
3. §3.1 台账的**状态字段与证据链接**

**被校验、不再视为并列真源（四项）**

| 对象 | 声明的语义 | 校验方式 |
|---|---|---|
| §3 关键路径 | 阶段主干的**编辑性摘要**，箭头表示"直接或传递前置" | 每条边须在依赖列中存在传递依据（检查 4）。**不生成**——"哪条链是关键路径"是人的编辑判断，不是图的输出，生成会毁掉编辑意图 |
| §9 并行波次 | 可并行组，**任务级** | 组内不得含任务与其直接依赖（检查 5） |
| 消费者列 | 真实传递下游的**子集**，不要求完备 | 声明的下游须在依赖链中存在（检查 7） |
| §10 矩阵 | **编辑性覆盖摘要**（§2.4） | 仅校验任务 ID 存在（检查 6） |

消费者列取"子集"而非"互为逆"，是刻意取舍：要求互为逆需修 131 处、大量在已签署行上；子集约束只需修 4 处，却仍能抓住真正的错误——声明一个在依赖链中根本不存在的下游。

## 5. 实现约束

1. **零新增第三方依赖。** 复用现成 devDependency `typescript` 与 Node 内建；不引入 markdown 解析库。参照 G2-03 复用 `collectModuleImports` 的先例。

2. **解析必须 fail-closed —— 本任务最重要的一条约束。** 检查器解析 markdown 表格，格式变动会让解析静默退化为"0 个任务、0 条边"，此时全部检查都会"通过"。因此必须：
   - 检查器输出解析计数（任务数、依赖边数、`R-*` 数、台账条目数、§3 边数、§9 组数）；
   - 计数低于登记的下限即**失败**（建议以 `1f53649` 实测值为基线登记：76 / 235 / 18 / 49 / 23 / 12，允许向上增长）；
   - 未能解析的表格行必须报错，不得静默跳过。
   这与 G2-03 要求输出"被扫描但导入列表为空的文件数"同源：**"跑过了"不等于"检查过了"。**

3. **例外只允许存在于显式登记表中，并 fail-closed。** 沿用 G2-03 的 `layering-registry.ts` 模式：
   - **已批准偏离**（检查 2）：登记 `{ 任务, 未满足的依赖, 依据 }`，如 `{ PA-15, PA-14U, 决策 C / PA-15 闸门报告 }`。未登记的不单调状态一律失败。
   - **非单任务证据文档**（检查 8）：登记 `G1-03-to-G1-06`、`G1-11-ci`、`G1-11-isolation-gates`、`PA-A4-A8`、`PA-A5-A6`、`engine-reassessment`、`incremental-pagination`、`poc-a-poc-b-chain-integrity` 等报告，以及 `PA-06B`/`PA-11A`/`PA-11B` 这类并入父任务记载的实施期拆分。
   - **历史波次**（检查 5）：登记 W1。
   登记表是单一手写真源，检查器只读它，不得在代码里另抄一份。

4. **检查 8 按引用关系判定，不按文件名约定。** 实测：按 `<任务ID>-claude-audit-report.md` 文件名匹配会产生约 20 处误报（多任务报告、非任务报告、并入父任务的拆分）。正确口径是：
   - 台账每行中的链接必须解析到存在的文件；
   - 每份 `*-claude-audit-report.md` 必须被至少一行台账引用，或在 §5.3 登记表中登记。
   台账行本就含 markdown 链接，此口径使用既有数据，不新增维护负担。

5. 遵守宪法 19 体量护栏（生产 300 预警 / 400 上限）。检查器宜按"解析 / 检查 / 报告"分模块，勿堆入单文件——G2-03 的 `phantom-dependencies.ts` 已达 349 行触发预警，是反面参照。

6. 不得用 `as any`、`@ts-ignore`、eslint 全局豁免绕过既有护栏；不得为让检查变绿而放宽任一检查或扩大登记表。
