## 0. 起草结论：拆成两棒，且 8s 预算很可能不必等增量架构

阶段一给的结论是「路径已定位、可达性有强证据、≤8s 待证明」。本轮起草前的核查把"路径"具体化了，结论有一处**优于**决策 #19 起草时的预期：

### 已核实的机制事实（不是推测）

| # | 事实 | 位置 / 证据 |
|---|---|---|
| 1 | **稳定化恰好 1 轮**，故整份重排 = **2 次完整渲染** | 清洁批次原始 evidence 四轮抽样，`stabilizationRoundMs` 均为单元素数组 |
| 2 | 热态两遍 ≈ **9390ms**，超 8000ms 预算 **+17.4%** | 探针 pass2 4732 + 批次最快稳定化轮 4638 + server 20 |
| 3 | 第二遍**不可省**的根据是 Chromium 能力触顶：`target-counter()` 与 `@page` 页边盒在 Chromium 150 不受支持 | [ADR-0010 §背景](../adr/0010-PA-11A目录页码两遍渲染与页眉页脚压印受控补偿.md) |
| 4 | **但收敛循环的存在另有原因**：`fillTocPageNumbers` 往**空占位 span** 填数字，宽度必变、可能重排，故须复测不动点 | [compose.ts:61](../../packages/pdf-export/src/compose.ts#L61) `<span class="toc-entry-page" …></span>` 为空 |
| 5 | `.toc-entry-page` **全仓无任何宽度约束** | `template-css` 仅由 DSL 产出 `.toc { break-before: page; }`（[css.ts:162](../../packages/template-css/src/css.ts#L162)），无 `.toc-entry-page` 规则 |
| 6 | 存在**非签署模板**的基础样式层 `PRINT_BASELINE_CSS`，当前仅一条 img/svg 规则 | [compose.ts:11](../../packages/pdf-export/src/compose.ts#L11)、[:33](../../packages/pdf-export/src/compose.ts#L33) |
| 7 | 项目**已有渲染后向 PDF 注入文本的签署先例**：页眉页脚压印受控补偿 + 文本层修复 | ADR-0010 决策 2；[cmap-repair.ts](../../packages/pdf-export/src/cmap-repair.ts) `repeatables` |

### 由此得到的判断

**事实 4/5 说明：第二次整份渲染的直接成因是"占位宽度不定"，而不是 Chromium 的能力边界本身。** 能力边界（事实 3）决定了"页码必须从产物大纲测量"，但没有强制"必须再整份渲染一遍才能把页码放进去"——事实 7 表明本项目已经有把文本注入已渲染 PDF 的签署做法。

**算术上**：若消除第二次整份渲染，热态**渲染段** ≈ `9390 − 4638 = 4752ms`。

> **引用口径（务必照此，勿把 4752 当全管线值）**：`4752ms` 只是渲染段。B 路径的全管线还要加大纲测量与回填，量级取批次 `postprocessMs` 十轮中位 **616ms**（区间 603–660，起草者与实施侧各自从原始 evidence 复算一致）→ **全管线 ≈ 5368ms ≈ 5.4s**，相对 8000ms 预算余量 **≈33%**。
>
> 统一表述：**「~4.8s 渲染 / ~5.4s 全管线」**。达标判断不受影响，但两个数不可混用。

**因此本任务书主张原子化拆分**：

| 棒 | 目标 | 预算 | 规模 |
|---|---|---|---|
| **2a** | 消除第二次整份渲染 + 正式复测 | **8s 全量重排** | 有界，改动集中在 compose/pagination 与基础样式层 |
| **2b** | 增量架构（受影响区 / 稳定页缓存 / 后台可取消 / 旧预览协调） | **1s 局部交互** | 大，ADR-0014 四项须真实编辑器验证 |

**拆分的理由与当初拆 A-04E 出来的理由完全相同：可归因性。** 把"能否达 8s"与"能否建成增量架构"放同一棒，任何红都无法判定归因——而 2a 有界、便宜、且其结果会改变 2b 的缓存设计（若整份重排已 ~4.8s，稳定页缓存的收益与形态都不一样）。

**决策 #19「范围必须含增量架构」不受影响**：2b 仍然必做，因为 **1s 局部预算无论如何达不到**（探针实测局部编辑仍走完整管线，21 页 4.6–4.9s）。本拆分只是把两个不同预算、不同机制的问题分开验收。

### D1　2a 消除第二次渲染的路径

| 候选 | 内容 | 评价 |
|---|---|---|
| **A** | 仅定宽，仍两遍渲染 | **不够**——收敛变确定但仍是 2 次整份渲染，9390ms 不变 |
| **B** | 定宽 + **渲染后把页码回填进 PDF 文本层**（扩展事实 7 的压印先例），只渲染一遍 | **推荐**——~4.8s 渲染 / ~5.4s 全管线，均达标；有签署先例；改动有界 |
| **C** | 用增量页缓存只重渲染目录页 | 属 2b 范畴，成本高得多，且 2a 的目的正是先便宜地拿下 8s |

**裁定：B**（业主 2026-08-07）。但必须同时满足 D2 的输出不变口径——若 B 无法满足，退回 A + 由 2b 承担 8s（届时 2a 只交定宽与持久会话，8s 顺延）。

#### B 的首个实现关口是**几何**，不是字形

实施侧起初把「回填数字的字形可得性」列为首关口，**该判断经双方复验为误，已校正**：

- [stamp.ts:63-65](../../packages/pdf-export/src/stamp.ts#L63-L65)：`stampChars` 集合显式包含 `"0123456789/ "`——**全部十个数字与斜杠、空格**；
- [stamp.ts:162](../../packages/pdf-export/src/stamp.ts#L162)：页脚一直在压印 `${headerText}${pageIndex + 1} / ${pageCount}`。

**0-9 的字形可得性在 PA-11A 签署管线中已经证过，不构成关口**（此处写明，免得实施期重新怀疑一遍）。

**真正的首关口**：[stamp.ts:68](../../packages/pdf-export/src/stamp.ts#L68) `assertStampBandsClear(...)` 的**零交叠自检**（交叠即 `PDF_EXPORT_STAMP_FAILED`）是为**页边距带**设计的；目录页码槽位在**内容流内**，几何前提不同。槽位为空（定宽而无字形）时理论上不交叠，**但须实测**：

- 引导点（leader dots）是否延伸进槽位；
- 槽位边界与相邻文本 run 的包围盒是否相切。

**这两条作为 B 的首个决定性反例**（§5.1）。

### D2　「输出不变」在产出方式改变后如何定义（**2a 的阻断项**）

[ADR-0013](../adr/0013-DEGRADE后排版引擎重评估.md) 出口 1 原文要求「**以输出不变为前提**证明 ≤8 秒」。B 把"再渲染一遍"换成"回填文本层"，**产出方式变了**，PDF 对象结构极可能不再逐字节相同。

**须裁定采哪一档**（我按严格程度排）：

1. **normalized sha 与现管线两遍产物全等**——最强，无需论证。**应先尝试**：若回填能做到规范化后字节全等，问题消失。
2. **语义/几何等价**：内容对账、几何 oracle、validator、CJK、双跑确定性**全部通过**，且差异逐项刻画（PDF 对象结构差异属实现细节，不影响交付物）。
3. 更弱的任何口径——**不接受**。

**裁定（业主 2026-08-07）：先试档 1；档 2 现在即明示为合法落点**（实施侧预判档 1 大概率够不着——数字嵌在原内容流的 CJK 子集字体，回填是独立 stamp 对象与独立文本算子，规范化后对象结构几乎必异；起草者认同，故预先授权，免得实施期再卡一轮）。

**档 2 的判定标准钉死为两条同时成立**（写进 §5.1 验收）：

1. **既有签署检查全过**：内容对账、几何 oracle、validator、CJK、双跑确定性；
2. **每一处结构差异逐条枚举**，并各自给出「为何不影响交付物」的理由。

**枚举不全即不算通过。** 「逐项刻画」是本棒的实质工作量，因此它必须是**可核对的清单**，不是一段开放式论述——开放式论述明确排除。

### D3　定宽落在哪一层（决定是否触碰签署模板）

- **基础层** [`PRINT_BASELINE_CSS`](../../packages/pdf-export/src/compose.ts#L11)：非模板 DSL、不动 PA-02/PA-04 签署面；
- **模板 DSL**：属签署物，改动须版本化 + validator + 快照重签 + 业主批准。

**裁定（业主 2026-08-07）：基础层，并一并授权快照重签走既有批准流程。**

起草者原标注为"未排除的风险"，**实施侧已独立确认为真**：基础层与模板 CSS 进同一个 `<style>`（[compose.ts:33](../../packages/pdf-export/src/compose.ts#L33)），新增 `.toc-entry-page` 宽度规则会改变**已签署基线 PDF 的目录页渲染**（页码列由自然宽变定宽），与"不动 DSL"无关。

更进一步：**B 路径本身就改变产出物，快照重签是 2a 的固有成本**，不是 D3 的副作用——故预先授权，不必开工后再回来请示。

**重签的边界（硬约束，写进 §5.1）**：

> 重签**只覆盖本次变更的预期后果**——① 目录页码列宽由自然宽变定宽；② 回填带来的产出结构差异。
>
> 快照中出现任何**预期之外**的差异，**停下报告**，**不得被"反正要重签"吸收掉**。

这条不写死，"重签"会变成遮羞布——正是本项目一路在防的形态。

## 5. 验收标准与最低证据

| 项 | 最低证据 |

| **标定门（决策 #22）** | **标定轮跑签署 main `f64f348db026590e44f44a639d14f5b55d5614c3` 的两遍管线，对旧签署带 [20553.4, 24300.2]**，批前批后各一次；正式十轮跑分支单遍管线。**不得为单遍管线另造未经签署的对照带**——用预测值校准机器健康是循环论证，机器漂移与产品变化将不可分辨。main 检出 HEAD 逐位不等即拒跑 |

| **占位替换守卫（原"定宽有效"位）** | 决定性测试：占位 `888` 替换为 **1 位 / 2 位 / 3 位**真实页码，三种情形均须通过两道几何门；**真非占位数字串（如正文中的 `123`）必须被拒**，不得被静默改写 |

| **持久会话** | 跨重排复用浏览器，冷启动只付一次；**取消后资源清理**（预算原文：取消后 2 秒内停止消耗主要计算资源），并须有"取消后同会话立即再导出成功"的确定性测试 |

| **确定性门（持久会话专用口径）** | 会话内连续产物经**签署口径**（`normalized-pdf-sha.mjs`，仅归一化 `D:\d{14}`）比对**必然不等**——Chromium 结构树 ID 计数器为**会话进程全局递增**，第二次打印不从 0 起（实测 200 处 `/ID (nodeXXXXXXXX)` 及其 `/Headers` 引用漂移；双归一化后逐字节全等）。故第二批须**另立口径**，且**必须是「按首次出现序规范化重编号」而非抹除**——抹除会使 `/Headers` 指错、结构节点增删、顺序错乱**全部不可检出**。四条约束同时成立：① 签署口径 `normalized-pdf-sha.mjs` **一字不动**；② 新口径限第二批用，与签署口径**并存并登记差异来源**；③ **交叉校验**——冷启形态产物上新旧口径须给出**相同判定**（分歧即新归一化写坏了）；④ **决定性反例**——构造 `/Headers` 换指或结构节点增删的 PDF，新口径**必须仍判不等**。缺 ④ 则"规范化"只是更花哨的抹除 |

| **测试串行化知情** | `--test-concurrency=1` 的引入理由、根因证据与**副作用**须在实施记录声明；**特别须给出：串行化是否使任何断言从"会红"变为"不会红"**。若是，那不是消除误伤而是降低检出能力，须单独裁定 |
