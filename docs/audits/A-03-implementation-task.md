## 3. 开工前必须裁定并回报的四件事

### D1　「结构确认」是什么？产物是什么？走哪条写路径？

**问题**：路线图任务名是「**结构确认**与语义编辑工作区」，[ux-spec §2](../ux-spec.md) 的流程也写「导入项目 → **识别结构并让用户确认** → 选择模板」。但 A-02 落地后，导入已经直接产出结构完整的 `document.json`（标题/列表/表格/图片均已成节点）。那么「确认」这一步到底在确认什么、用户能改什么、改完产出什么？

现有文档**没有任何一处定义它**——我全仓查过，`结构确认` 只在路线图任务名里出现一次。

**候选口径**：

1. **只读复核**：把导入结果的结构摘要（层级、节点计数、被降级/丢弃项）呈现给用户确认，不产生编辑；确认动作只是流程推进。
2. **可纠正复核**：允许用户改正结构识别错误（例如把误判为段落的行提升为标题、合并被拆散的列表），产物是**一组走 PB-03 事务的编辑操作**。
3. **不设独立步骤**：结构确认并入编辑工作区本身，用户直接在工作区里改。

**我的建议：② 可纠正复核，且产物必须是普通事务**——理由是它同时满足 ux-spec §2 的流程语义与「不引入第二条写路径」这条硬边界；①太弱（用户看到错也改不了，与「让用户确认」的承诺不符），③丢掉了 ux-spec 明写的流程节点。

**须裁定并写入 ADR-0030**：口径、用户可执行的纠正动作清单、以及确认步骤是否可跳过。

### D2　编辑工作区在冻结 1.0.0 状态机里的位置

**问题**：[冻结状态机 1.0.0](../../packages/ux-state/src/states-1.0.0.json) 的 12 态里**没有「编辑中」**。A-02 已经确立：成功/取消/整体失败落到**非状态机**的 `project-view`（[ADR-0029](../adr/0029-A-02导入入口file.import.select冻结与覆盖落盘裁定.md)），并且 A-01-followups #4 的 additive 纪律禁止静默改 1.0.0。

**因此本棒绝不能发明第 13 态。** 但必须裁定：

1. 编辑工作区是 `project-view` 的一种呈现，还是需要新的非状态机视图类型？
2. **D1 若取 ② ，结构确认步骤要不要状态？** 若要，那就是 1.0.0 的语义扩展——须走 [host-contract §5 同款版本化流程](../host-contract.md) + 业主批准，**不能在本棒顺手加**。

**我的建议**：工作区与结构确认**都不进状态机**，作为 `project-view` 的呈现分支实现；若日后确需状态，另开版本化小棒。**理由**：1.0.0 刚由 A-01 契约加固棒完成 12 态 × 5 字段逐字锚定（[A-01-minor3-claude-audit](A-01-minor3-claude-audit.md)），此刻扩它的代价最高、收益最低。

### D3　A-03 与 A-05 在「普通表格 / 图片」上的分界

**问题**：两行的范围**字面重叠**：

- `A-03` 范围：文字、标题、列表、**普通表格、图片**
- `A-05` 描述：附件、**图片替代文本**与**普通表格编辑**

不裁定的话，实施者要么两头都做（越界）、要么两头都不做（留洞），而我在审计时无从判断哪种才算对。

**我的建议**：按「**结构 vs 内容**」切：

- **A-03**：把表格/图片当**结构节点**处理——插入、删除、移动、在工作区中正确渲染、键盘可达、稳定 ID 与 undo/redo 覆盖它们；表格的行列增删属结构操作，归 A-03。
- **A-05**：单元格**内容**编辑、表头语义标记、图片 alt 文本、附件上传与尺寸/数量上限预检。

**须裁定**：接受此切法或给出替代，写入 ADR-0030，并在 A-05 开工时反向引用。

### D4　两条停止条件的可判定口径（**最重要的一条**）

停止条件是 A-03 唯一的阻断级要求，现在两条都不可判定。

**（a）「主线程冻结」**——须给出：阈值、语料、机器、测量方法、判定统计量。

**我的建议**（全部引用既有权威值，不新增阈值）：

- 阈值取 [性能预算](../performance-budgets.md)原文：**普通键入/选择响应 p95 ≤ 100 ms**；并采其稳定性预算「关键操作不得出现未响应超过 2 秒且没有进度/取消反馈」作为**硬阻断线**；
- 语料：**30,000 字**（预算原文的首战上限），须落成可复跑 fixture，不得临时生成；
- 机器：G1-14 参考机器 `wenshu-dev-primary`，按 [reference-machine §3 性能采样协议](../reference-machine.md)执行（重复 10 次，取 p95）；
- 判定：**测量必须落成机器可判的证据文件**，不接受「体感不卡」。

**（b）「结构丢失」**——我建议操作化为三条同时成立，任一破即阻断：

1. 任意编辑序列后，除**显式删除**的子树外，**既有稳定 ID 集合完整保留**（PB-03 提交前已有此校验，本棒须在 UI 层端到端复验）；
2. 每次提交后文档通过 G1-04 `validateDocument`；
3. undo/redo 往返后与提交后文档 **deep-equal 且不重分配 ID**（[ADR-0016](../adr/0016-PB-03统一编辑事务边界.md) 后果段原文）。

**须裁定**：以上口径是否采纳；采纳后写入 ADR-0030，**并且必须各配一条决定性测试**——变异（放宽守卫）即变红。

## 4. 硬边界（越界即停）

1. **唯一写边界。** 所有文档写入必须经 `@wenshu/editor-transactions`。[ADR-0016 决策 #5](../adr/0016-PB-03统一编辑事务边界.md) 原文：`@wenshu/semantic-editor` 不再导出 raw 操作，它们只作为 `/internal` 供事务包使用，**没有 UI、持久化或 AI 工具可以此为应用写入口**。
   **审计会 grep**：UI 侧任何对 `@wenshu/semantic-editor/internal` 的直接引用、任何绕过 `TransactionManager` 的文档突变，**直接 BLOCKER**。
2. **不发明第 13 态**（A-01-followups #4；见 D2）。
3. **不改 G1-04 schema、不改稳定 ID 规则、不改 `states-1.0.0.json` 一个字节。** 若发现必须改，**停下报告**，不得顺手改。
4. **独占编辑器模块**（路线图原文）：本棒独占编辑内核与工作区 UI；并行任务须模块隔离。
5. **分层**：`semantic-editor` / `editor-transactions` 是 **L1**，工作区 UI 属 **web** 层——不得把 UI 逻辑下沉进 L1，也不得让 L1 反向依赖 UI（G2-03 分层门禁会拦）。
6. **不引入新的第三方运行时依赖**而不经决策记录；ProseMirror 已在 lockfile（`prosemirror-model`），新增任何编辑器相关依赖须走 [supply-chain](../supply-chain.md) 流程。

## 5. 验收标准与最低证据

路线图的四项完成证据，逐项给出**可核验**形式：

| 完成证据（原文） | 最低证据 |
|---|---|
| **键盘编辑** | 全部结构操作（增删改标题/段落/列表项/表格行列/图片节点、移动、undo/redo）**仅用键盘**可完成的 E2E；含焦点可见、Tab 序合理、无鼠标依赖。**不做完整 WCAG AA**（归 A-13），但键盘可达是本棒硬要求（ux-spec §4 各态 `a11y.focusEntry` 已冻结） |
| **稳定 ID** | 固定种子长编辑序列（建议 ≥120 步，与 PB-02 同口径）逐步断言：ID 全局唯一、未受影响 ID 保持、复制递归分配新 ID；**位置派生 ID 的负向变异必须变红** |
| **undo/redo** | 往返 deep-equal 且不重分配 ID（ADR-0016 原文）；含事务中途取消（`AbortSignal`）→ `rolled_back`、不暴露部分文档 |
| **30k 字响应预算** | 参考机器上 30,000 字 fixture、重复 10 次、p95 ≤ 100 ms 的**原始采样数据落盘**；同时证明无 >2 s 无反馈操作 |
| 停止条件（a）主线程冻结 | 同上，且须有长任务分片/移出主线程的实证（预算原文「长任务必须移出主线程或分片」） |
| 停止条件（b）结构丢失 | D4(b) 三条各一条决定性测试 + 变异自证 |

**变异自证**（沿用近三棒纪律）：至少覆盖「唯一写边界」「稳定 ID 保持」「undo/redo 不重分配」「结构丢失三条」，每条变异后**必须因正确原因变红**——红在别处即探针失效，作废重做。全部改回后逐文件 sha256 与 HEAD 一致。

**测试层级**：单元（操作层/视图模型）+ 契约（G1-04 往返、ID 不变量）+ 集成（TransactionManager 真实事务）+ **E2E（真实 Electron 壳键盘编辑，沿用 PB-12/A-02 编排器）** + 性能采样。

## 9. 独立审计的猎杀方向（预告）

1. **唯一写边界**（第一个查）——全仓 grep UI 对 `semantic-editor/internal` 的引用；自构一条绕过 `TransactionManager` 的写路径，必须结构性失败；变异 ADR-0016 的 capability 守卫看是否变红。
2. **稳定 ID 真不变**——自建长编辑序列，重点打复制/移动/撤销后重做；位置派生 ID 变异必须红。
3. **undo/redo 不是假往返**——比 deep-equal 之外还要比 ID 集合；构造「undo 后编辑再 redo」的分叉场景。
4. **性能证据是否可复现**——不采信汇总数字，要原始采样；核语料真是 30,000 字、真跑 10 次、真在参考机器；注意运行时版本偏差如实登记。
5. **结构丢失三条是否各自承重**——逐条变异，红必须落在对应断言上，不接受邻近守卫代打。
6. **第 13 态**——`states-1.0.0.json` 的 `git diff` 必须为空；工作区若引入新视图类型，核它确实在状态机之外。
7. **A-05 边界**——按 D3 裁定逐项对照，既不越界也不留洞。
8. **fake 边界**——E2E 键盘输入必须是真实事件进真实壳，断言层必须是真文档真 ID；scripted 对话框注入沿 PB-10/12/A-02 先例属合法。
9. **台账与流程**——报告同轮补 §3.1 行；报告文件随 PR 落盘（死链教训）；提交指纹逐位比对（审的代码=签的代码）。
