# G2-01 功能变更治理门禁独立审计任务书（交给 Claude）

> 日期：2026-07-21　实施基线：`feat: freeze G2-01 definition of done and review gates` 提交　报告目标：`docs/audits/G2-01-claude-audit-report.md`

## 1. 角色与写入边界

你是独立只读审计者。只允许新增/修改上述审计报告；不得修改治理文件、代码、路线图或工作流。

## 2. 审查要点

- **覆盖完整性**：DoD 逐项覆盖路线图 G2-01 行要求的七个维度（测试、文档、迁移、回滚、可访问性、安全、产物），无缺项、无弱化为口号的条目（每条可被判定"不满足"）。
- **反例有效性**：任取 DoD 反例表 3 行，验证所述拦截条目确实存在且能拦截；构造一个"注释失败测试变绿"或"守卫代打"的反例任务，确认按 DoD 无法判完成。
- **机制衔接**：DoD 与既有可执行门禁（quality 护栏、层级审计、verify、独立审计流程）不矛盾、不重复发明；PR 模板与 GitHub 工作流兼容；评审清单不替代独立审计的表述明确。
- **无治理降标**：不得因单人开发取消评审/独立审计；缺陷标准确为"先红后修"；关闭权在审计角色。
- **边界**：本批纯治理文件；功能代码、CI 作业定义、冻结契约、路线图任务行零漂移（G2-01 台账行除外）。

## 3. 结论规则

- 维度缺项、反例实际可蒙混、评审/审计被弱化、或夹带功能变更：`FAIL — G2-01 不得完成，功能 PR 不得开始`。
- 无 BLOCKER/MAJOR 且 MINOR 有归属：可给 `CONDITIONAL PASS`；完全满足给 `PASS`。审计者只给结论，由 Codex 完成台账。
