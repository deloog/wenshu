## 3. 开工前必须先裁定并回报的三件事

### D1　导入入口 —— **业主已裁定：走选项①，冻结 `file.import.select`**

**裁定（业主，2026-08-01）**：**不接受**"Alpha 不提供任意位置选文件"的产品收窄。因此本棒**冻结 `file.import.select` 的 payload schema**，用户可在任意位置选取导入源。任务书审计给出的"选项②"裁定按其自身条款（"业主若不接受收窄则自动失效回①"）作废。**该裁定须按仓内惯例落成一条决策记录条目**，与 ADR-0029 互相引用。

**这条裁定把 A-02 从 UI 任务升级为「契约任务 + UI 任务」**：走 [host-contract §5](../host-contract.md) 的版本化流程 + ADR + 消费者契约测试 + 独立审计，工期与审计强度相应提高。以下三条是①绕不开的子裁定，须一并写入 ADR-0029：

**① -a　输出绝不能是路径（这是 R-HOST 的红线，也是最容易破的地方）**

[host-contract §4](../host-contract.md) 明写"文件与目录位置由 Host 保管；核心只使用受控 `grant_id`、资源 handle 和安全文件名"，且值级预检对**任意字段**结构性拒绝盘符绝对路径、POSIX/UNC、`file:` URL 与穿越片段（G1-09 NF-02 已闭合，PB-10/PB-11 我逐项复验过）。

因此 `file.import.select` 的 **output 不得包含任何路径**——选中文件后应返回**不透明 handle 或作用域限定到该文件的 grant**，真实读取仍在特权进程内完成。**把绝对路径塞进 output 会被现有预检直接拒掉**（届时不要去放宽预检，那是把红线拆了）。

**① -b　协议版本形态须书面裁定**

我核过 [contract.ts `validateDeclarationConsistency`](../../packages/host-contract/src/contract.ts) 的实际不变量：判定是**按 `capability_version` 逐项**做的——`0.2.0` 的能力必须在冻结集内且用 `/0.2.0` schema ID，其余必须用 `/0.1.0` 占位 ID。**并没有"注册表必须恰好把这 7 项登记为 supported"的强制**。所以把冻结集从 7 扩到 8 **不会使既有 0.2.0 注册表失效**（未实现该能力的 host 继续用 `/0.1.0` 占位即可）。

但仓内对"向冻结契约增内容"的既有纪律是 **additive 次版本 + 保留冻结版 + 双版本 reader**（PA-06B 证据契约 1.0.0→1.1.0、PA-08 检出报告 1.0.0→1.1.0 皆如此）。二者不冲突但形态不同，**须在 ADR-0029 里选定其一并给出理由**，且补一条决定性测试：**既有 0.2.0 注册表（把 `file.import.select` 登记为 `/0.1.0` 占位）仍须校验通过**。

**精确化注记（任务书审计 NOTE-1 / R-1 红线）**：0.2.0 无任何"读"原语；handle/grant 之后的真实读取沿用 PB-11 先例（特权进程内 L2、grant 边界 fail-closed），**契约层不得新增读原语**（`file.read` 之类出现即 BLOCKER）。handle 生命周期与单文件作用域按审计报告追补二 R-2/R-3 写入 ADR-0029。

**① -c　平台选择器只能在 L3 壳内**

真实文件选择对话框属平台能力，只能出现在 L3 壳（`apps/electron-shell`，`dialog.showOpenDialog` 已有先例）。**不得**在 web 层或 L0/L1/L2 出现任何选择器实现，**也不得**让壳旁路协议直接把结果喂给核心——必须经 `0.2.0` 协议回传 handle。

### D2　覆盖/合并策略（[PB-11-followups #6](PB-11-followups.md) 的关闭点就在这里）

PB-11 的导入语义是**目标目录必须事先不存在**，且"PB-11 不提供原地合并语义"。A-02 要在 UI 流程里明确：目标已存在时是**拒绝**、**另建新目录**、还是**引导用户另选**？

裁定必须与停止条件"**任何原地修改即阻断**"相容——即：**不得**出现"合并进已有项目目录"的路径，除非业主另行批准并更新路线图该行。

### D3　原件落盘布局与保护登记（[PB-11-followups #4](PB-11-followups.md) 的关闭点）

PB-10 的原件保护按 **grant 根下安全平文件名**判定，Host 写能力只能寻址 grant 根直下文件；PB-11 的材料落在 `targetRoot/truth/materials/` 子目录，对 Host 写**结构性不可达**。

A-02 若**改变原件落盘布局**或**引入可寻址子路径的写能力**，就必须重估登记模型——**登记名须与真实落点一致**，不得默认现有平文件名登记充分。请在开工前明确 A-02 的导入落盘布局，并说明它是否触发重估。

## 4. 硬边界（越界即停）

1. **原件只读，任何原地修改即阻断**（路线图停止条件）。导入原件的**字节与哈希在全流程后必须不变**——这是本棒唯一的停止条件级要求。
2. **导入文件名按[决策 #7](../../决策记录.md) 处理**：导入时安全规范化重命名，判定矩阵见 [document-model §7](../document-model.md)（远程 URL / 越根路径拒绝、冲突 fail-closed）。**以该节现行表格为准、逐行对账，不在本任务书里复述行数**——PA-00 签署后该矩阵已追加过行（`70f2395` 补 gif/bmp），任何硬编码计数都会过期（同 G2-04 承接③"涉计数直接引用来源、不自行计数"）。**不得原地放宽 `0.1.0`，不得自行发明命名规则。**
3. **必须调用 `protectImportedFile` 登记原件**（[PB-10-followups #1](PB-10-followups.md) 的"要求"仍是活的行为约束，尽管该条已由 PB-12 关闭）；未登记的既有文件仍可被 `overwrite:true` 覆盖。
4. **状态呈现必须消费 A-01 冻结契约**：`empty-project` / `importing` / `import-partial` / `permission-denied` 四态的 `requiredPresentation`、`forbiddenSemantics`、`a11y` 是**契约义务不是建议**；`stateVersion 1.0.0` 已冻，演进须新 schema + 双版本 reader（[A-01-followups #4](A-01-followups.md)），**不得静默改 1.0.0 语义**。
5. **web 层纯净**：`apps/web` 只能依赖 L0/L1，禁 `node:*`/`electron`/`@ohos`；eslint 已封 `process`/`Buffer`/`globalThis.process` 等全局，**不得为绕开而加豁免**。
6. **平台能力只经 `0.2.0` Host 协议**；权限拒绝须走 `HOST_PERMISSION_DENIED` + 显式降级枚举，不循环弹窗。
7. 分层与体量护栏照常；**新建 workspace 须先停止上报业主**，不得自行修改冻结的分层归属表。

## 5. 验收标准与最低证据

| 验收点（路线图完成证据） | 最低证据 |
|---|---|
| **原件哈希不变** | 导入前后对原件做**字节级**比对；异常路径（取消/失败/权限拒绝）后同样比对。这是停止条件级要求，须有**决定性测试**：变异写入路径使其触碰原件 → 测试因正确原因变红 |
| **取消** | 真实文件 E2E 中途取消：`cancelled` 终态（不伪装成 failure）、无半包/半写、原件不变 |
| **部分失败** | 对应 `import-partial` 状态：成功内容、失败附件、原因、可重试项**逐项呈现**；契约的 `forbiddenSemantics: ["不整体吞掉结果"]` 必须被真实满足 |
| **权限拒绝** | 真实只读目录/拒绝授权 → `HOST_PERMISSION_DENIED` + `fallback` 明确；不回显系统路径；不循环弹窗 |
| 状态契约一致性 | 四态的呈现义务可对账到 `@wenshu/ux-state` 1.0.0；建议做成可机检断言而非人工比对 |
| E2E 真实性 | 真实文件、真实目录、真实 Host 协议；fake 只允许在**尚未实现的下游**边界，不得 mock 文件系统/存储/Host |
| 决定性守卫 | 每条承重守卫变异后对应测试**因正确原因**变红（DoD §2） |

## 9. 独立审计的猎杀方向（预告）

- **原件哈希不变**——我会在取消、部分失败、权限拒绝三条异常路径上各做一次字节级比对，并变异写入路径看守卫是否决定性；
