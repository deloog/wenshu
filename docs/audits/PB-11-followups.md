# PB-11 后续承接项

> 非阻断项，首审 FAIL 修复轮（2026-08-01）登记，供 PB-12/A-02/A-11/A-15 归口查阅。
> 来源：Claude 首审报告 MI-01/MI-02/NOTE 与修复轮裁定。

## 1. 知识包签名与外部信任锚 → PB-12 闸门 / A-15 安全专项

- **内容**：包自带 manifest 即信任根；攻击者同步改写真源字节与 manifest 中的
  sha256（自洽改写）时导入成功，不可检出。业主 2026-08-01 书面批准口径收窄：
  PB-11 只保证检出单点/不自洽篡改。
- **要求**：PB-12 闸门与 A-15 安全专项评估是否引入签名/外部锚（密钥管理、
  分发与轮换需另行 DoR）；在此之前任何文档不得宣称知识包可抵御自洽改写。
- **已记录于**：ADR-0026 §7.1 / docs/project-contract.md §3 / PB-11-implementation-record §7。

## 2. 解压炸弹残余威胁模型 → A-15

- **内容**：`readZip` 已加廉价上限（条目 ≤1000、单条解压 ≤64 MiB、总量
  ≤256 MiB），但这是固定经验值，不是完整威胁模型（如多层嵌套、侧信道计时、
  内存压力组合）。A-15 明列"压缩炸弹"属安全专项。
- **要求**：A-15 对不可信归档输入做专项评审时复核上述上限的充分性。

## 3. 强杀孤儿临时目录 → PB-12

- **内容**：导入使用 `<targetRoot>.wenshu-import-<uuid>` 同级临时目录；正常失败
  路径会清理，但硬杀进程会留下该目录，而 PB-10 的 `recoverGrantDirectory` 只清
  `.wenshu-tmp-*` 前缀，两套前缀互不覆盖。
- **要求**：PB-12 端到端强杀场景覆盖一次孤儿目录回收（清理或如实登记）。

## 4. 原件保护的平文件名模型边界 → A-02 / A-11

- **内容**：PB-10 保护模型按 grant 根下安全平文件名判定；Host 写能力只能寻址
  grant 根直下文件。PB-11 导入的材料落在 `targetRoot/truth/materials/` 子目录，
  对 Host 写结构性不可达；登记的平文件名覆盖 Host 唯一可寻址的同名位置。
- **要求**：A-02/A-11 若引入可寻址子路径的写能力，或采用不同的原件落盘布局，
  必须重估登记模型（登记名须与真实落点一致），不得默认现有平文件名登记充分。

## 5. `formal_versions` 非空未实现 → 未来需求

- **内容**：多版本正式版本的历史文档/模板打包未实现，当前测试使用空数组。
- **要求**：需求明确后扩展，导出/导入两侧同步演进并补 round-trip 测试。

## 6. 覆盖/合并策略 → A-02 / A-11

- **内容**：导入要求目标目录事先不存在；覆盖/合并由 Host 层决策。
- **要求**：A-02/A-11 在 UI 流程中明确策略，PB-11 不提供原地合并语义。

## 7. grant 边界不解析 realpath → A-15（与 PB-10 MI-05 残余同类）

- **内容**：`assertTargetWithinGrant` 是字符串包含判定，不解析符号链接——
  授权目录内若存在指向外部的符号链接，字符串上“在 grant 内”而实际落在外面。
  与 PB-10 MI-05 残余同类；Windows 建符号链接需权限，未实测。
- **要求**：A-15 安全专项统一评估符号链接/联接点穿透（含 PB-10 残余），
  必要时引入 realpath 规范化。
