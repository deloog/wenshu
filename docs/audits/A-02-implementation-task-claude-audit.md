## 3. 三项裁定（业主书面委托："我建议后者，但这是你的裁定"）

### D1 裁定：**选项②**——不冻结 `file.import.select`，只用已冻结能力 + grant 边界内进程内读取

理由：
1. 事实底座成立（§1.1）：冻结面恰 7 项，`file.import.select` 确为 `unsupported` 占位。
2. 选项①把契约任务（版本化 + ADR + 消费者契约测试 + 独立审计）压进 UI 任务，扇出风险与业主建议一致，不取。
3. ux-spec（§2"新建/导入项目"、§4 状态表）与 A-01 冻结面**均未规定任意位置文件选择器**，②不与任何冻结 UX 冲突；PB-11 已提供"grant 边界内进程内读取"的已审先例，②不发明新面。

**两个强制条件（写入 ADR-0029，缺一裁定自动失效回①）：**
- 读取路径必须沿用 PB-11 先例——Electron 壳特权进程内 L2 读取、grant 边界 fail-closed；**不得**为 web/契约层发明新读原语，不得让 Electron 壳旁路 0.2.0 协议自建选择器（那会同时违反硬边界 #6 与 G2-03 分层）。
- UX 收窄必须书面化并报业主确认：Alpha 导入源须落在已授权目录内，本棒**不提供任意位置文件选择**；若业主后续要求任意位置选文件，`file.import.select` 冻结另立契约任务，不回灌 A-02。

### D2 裁定：**拒绝 + 引导用户另选/另建新目录；禁止任何"合并进已有目录"路径**

- 目标目录已存在时，合规动作集合 = {拒绝并说明, 另建新目录, 引导用户另选}，可任选或组合；**merge-into-existing 契约级排除**——它与停止条件"任何原地修改即阻断"和 PB-11"不提供原地合并语义"直接冲突，未经业主另行批准并更新路线图该行不得出现。
- 冲突呈现须守 document-model §7.2 同款口径：内容不同即拒绝，**不静默换名**；权限/冲突走 `HOST_PERMISSION_DENIED` 或显式冲突态，不循环弹窗（ux-state 1.0.0 `permission-denied` 冻结义务）。

### D3 裁定：**不得引入可寻址子路径写能力；布局二选一，登记名与真实落点一致**

- Host 写仍只能寻址 grant 根直下平文件名（维持 PB-10 已审模型）。**不触发 PB-11 #4 重估就是本棒最稳路径**；任何子路径寻址写立即升为范围外事项回业主。
- 原件落盘布局二选一，均须在 ADR-0029 声明：
  - (a) **原件原地保留**（只读不复制）→ `protectImportedFile` 按 grant 根平文件名登记，与 PB-10 模型逐项一致，零重估；
  - (b) **复制入项目子目录** → 子目录对 Host 写结构性不可达（PB-11 已审模式），登记平文件名覆盖 Host 唯一可寻址同名位置，ADR 中须给出该等效性论证。
- 无论哪种，登记名与真实落点一致性纳入 A-02 实施审计的决定性检查项。

## 追补二（2026-08-03）：红线升格 + handle 两条设计点登记

业主回执确认三条底座核查一致，并补两个①路径下绕不开的设计点。以下登记进入实施审计猎杀清单，与①-a 并列。

### R-1（升格为红线，与①-a 并列）：契约层不新增读原语

冻结 `file.import.select` 最自然的滑坡是"顺手再冻一个 `file.read`"。钉死：选择器返回 handle 之后的**真实读取必须仍沿用 PB-11 先例**——特权进程内 L2 `node:fs`、grant 边界 fail-closed；**契约层不得新增任何读原语**。实施中若出现 `file.read` / `file.content.read` 之类能力名进入 schema、registry 或 handler 分派，直接 BLOCKER。

### R-2（设计点）：handle 的生命周期与吊销——ADR-0029 必须定死

事实底座已核：PB-10 `GrantTable` 已有 `revoke(grantId)`（`grants.ts:23`、实现 `:62-64`），吊销机制存在，但 handle 语义未定。ADR-0029 须写明：会话内一次性 / 可重放 / 进程重启后是否失效，三态择一并给理由。**一个可重放且不过期的 handle = 把"任意位置的那个文件"变成永久授权**，那正是走①换来的便利所付的代价。
**反例要求（决定性测试）**：吊销后再用该 handle → 必须 fail-closed（稳定错误码），变异守卫（删掉吊销检查）须变红。

### R-3（设计点）：handle 作用域钉死为单文件

事实底座已核：既有 `DirectoryGrant` 是**目录级**作用域（root + mode），单文件作用域是**新语义**——这更说明必须书面定死，不能靠实现惯性滑成目录级。用户选了 `D:\x\y\报告.md`，返回的 handle 只覆盖该文件，**不得隐式授权 `D:\x\y\` 整目录**。
**反例要求（决定性测试）**：拿该 handle 读同目录另一个文件 → 必须被拒；变异守卫（作用域校验放宽为目录前缀匹配）须变红。
