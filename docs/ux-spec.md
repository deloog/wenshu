# 文枢 UX 基线（G0）

> 状态：G0 首战 UX 约束已批准（2026-07-20）。它规定工作流和状态，不提前制作完整视觉设计系统。

## 1. 首战体验目标

用户第一次使用应感受到：“把草稿和资料交给文枢，它帮助我形成一份可直接交付、仍可编辑和可追溯的专业报告。”核心成功不是生成一段文字，而是得到通过检查的 PDF 成品。

## 2. 首条端到端流程

```text
新建/导入项目
→ 识别结构并让用户确认
→ 选择专业模板
→ 生成分页预览
→ 查看页面问题与出处
→ 自然语言或直接编辑局部修改
→ diff + 接受/拒绝 + undo
→ 导出前检查
→ PDF 交付
→ 保存版本/知识包
```

任何阶段都必须让用户知道：系统正在做什么、使用了哪些材料、哪些是 AI 建议、是否已保存、失败是否影响原文、下一步如何恢复。

## 3. Alpha 信息架构上限

- 项目/文件夹与最近项目
- 文档编辑区
- AI 工作区（目标、约束、计划、diff 与裁决）
- 页面预览与问题检查
- 引用/出处查看
- 版本历史
- 导出与完整知识包
- 设置（模型/BYOK、字体、隐私、存储）

不加入知识图谱视图、模板市场、自动同步、多端协同、复杂表格或 PPT。

## 4. 核心状态矩阵

| 场景 | 必须呈现 |
|---|---|
| 初次/空项目 | 支持的输入、示例和下一步，不出现无意义空白编辑器 |
| 导入中 | 文件名、阶段、进度、取消；原文件只读 |
| 导入部分成功 | 成功内容、失败附件、原因和可重试项，不整体吞掉结果 |
| AI 处理中 | 使用的模型/材料范围、可取消、预计费用或 BYOK 状态 |
| AI 结果 | 变更范围、diff、出处、accept/reject；未接受不改正式内容 |
| 分页中 | 当前阶段和可取消；旧预览保留到新结果可用 |
| 页面有问题 | 类型、严重度、页码、定位、建议与允许的人工豁免 |
| 保存成功/失败 | 明确保存位置和版本；失败不假装已保存 |
| 导出前 | 格式承诺、字体/引用/页面检查结果、目标路径和覆盖风险 |
| 离线/模型不可用 | 本地编辑、排版、检查和导出继续可用；AI 功能解释降级 |
| 权限拒绝 | 为什么需要、当前可做什么、如何重新授权；不循环弹窗 |
| 崩溃恢复 | 恢复到哪个检查点、可能丢失什么、是否另存恢复副本 |

## 5. AI 交互原则

- 先表达目标、受众、约束、不可改和不可猜项，再让模型规划。
- 计划不是最终结果；用户批准的是具体 diff 或正式版本。
- 所有 AI 修改可撤销；批量/跨章节修改先预览影响范围。
- 引用与生成内容视觉上可区分，但不通过过度徽章制造噪声。
- 模型不可用时，编辑、模板、分页、检查和导出仍是完整可用能力。

## 6. 排版与页面检查

- 编辑视图与页面预览明确区分，避免用户误以为流式编辑区就是最终页面。
- 页面问题按“阻断交付 / 建议修复 / 信息”分级；阻断项未处理不得默认导出正式版。
- 自动修复必须展示将改变的节点和页面；允许撤销并保留修复前版本。
- 用户可对特定问题作有记录的豁免，系统不得无限重复同一建议。

## 7. 删除、覆盖与导出

- 删除项目、覆盖文件、破坏性迁移和清空历史需说明范围并二次确认。
- 默认另存成品，不覆盖导入原件。
- 导出界面明确 PDF/docx/知识包/Markdown 的不同质量承诺。
- 后台导出失败时保留项目和上一次成功成品，提供诊断而非裸错误。
