# PoC-A 实验说明：排版生死闸

> 版本：1.1　日期：2026-07-20　状态：已冻结（业主批准右删失基线修订）  
> 本实验只回答：廉价 Chromium HTML/CSS 打印路径能否把固定结构化长文稳定生成 10–20 页可交付 PDF，并自动发现关键分页问题。它不验证完整编辑器、AI 写作、知识层、同步或 docx 保真。

## 固定输入与环境

- 内容：`docs/poc-a/fixtures/golden-report.md`，fixture 版本 `1.0.0`；正文目标 8,000–12,000 个中文字符，含三级标题、2 张普通表、2 张图、长 URL/英文、列表、引用、脚注式来源和附录。正文事实均为合成数据，只用于排版。
- 数据：`report-data.csv`；图：`chart-overview.svg` 与 `chart-process.svg`；不得在实验过程中替换成更容易排版的内容。
- 模板：`formal-business.template.json` 版本 `1.0.0`，A4 纵向；封面、自动目录、正文、页眉页脚、表格、图片、来源和附录规则固定。
- 字体：Adobe Source Han Sans CN 2.005R 静态 OTF，仅 Regular、Medium、Bold；G1 从官方 release 下载后记录文件名和 SHA-256。所有测试机器使用同一字体文件，禁止依赖系统同名字体。
- 主环境：G1 锁定的 Windows 11 64 位、Chromium/Electron 版本、100% 系统缩放、96 CSS dpi、A4、背景图形开启、页边距由模板控制、浏览器默认页眉页脚关闭。
- 重复性：每次实验记录 OS、渲染器完整版本、模板/fixture/font 哈希和打印参数。

## 最小模板规则

- 页面：A4；上/下 20mm，内/外 18mm；正文区域不得越界。
- 层级：封面独立页；目录独立起页；一级标题新页起；标题不得成为页尾最后一项；标题后至少保留两行正文。
- 正文：11pt、1.55 行距；中文标点禁行首/行尾按可实现能力检查；段落 widow/orphan 最少 2 行。
- 页眉页脚：封面无；正文页眉显示报告短标题，页脚显示 `当前页 / 总页数`；目录页码必须与正文实际页一致。
- 表格：表头重复；禁止横向越界和文字遮挡；不能完整容纳的行移至下页；不把单行拆成两页。
- 图片：保持比例、不得超出版心；图片与题注同页；题注后保留来源；不得遮挡正文。
- 来源：引用编号可追到来源列表；长 URL 允许换行但不得越界。

完整声明见固定模板 fixture；第三方任意 JavaScript、网络和文件访问均不在实验范围。

## 自动检查清单

| 级别 | 必须检查 |
|---|---|
| P0 阻断 | 页面/内容丢失或重复、正文/表格/图片越界或遮挡、空白关键页、目录页码错误、字体缺失、PDF 无法解析 |
| P1 严重 | 标题落页尾、标题与首段分离、表头未重复、表格行被错误切断、图片与题注分离、孤行/寡行、异常大块空白 |
| P2 建议 | 页面疏密异常、连续短页、图片过小、来源 URL 断行难读、视觉节奏不一致 |

另制作至少 12 个单故障变体，覆盖每类 P0/P1。检测器必须检出全部 P0，P0+P1 总检出不少于 10/12；同一正常样本的误报不得超过 2 项，且能定位到页码和内容节点。任何规则暂时无法自动检测，必须显式列为人工检查，不能假装已覆盖。

## PDF 合格标准

1. 产物为 10–20 页 A4 PDF，可在两个独立 PDF 阅读器打开、搜索和复制正文。
2. 连续运行 3 次：页数、目录页码、P0/P1 结果和关键元素几何值一致。
3. 无 P0；P1 为零或仅有记录原因并获人工接受的非系统性个案；不得逐页手调格式。
4. 正文、表格单元格、图片和来源与 fixture 对账，无丢失、重复、截断或非预期重排。
5. 字体预检无缺失，并保存 PDF 字体检查结果；视觉抽检无 fallback 造成的明显换行漂移。
6. 固定页渲染图通过视觉回归；所有超过阈值的变化均经人工逐页审查。
7. 在参考机器上，完整重新分页 ≤8 秒、页面检查 ≤5 秒、30 页以内 PDF 导出 ≤30 秒；任务可取消且失败不损坏输入。

## WPS/Word 对照

0 号用户对同一 fixture 分别用 WPS、Word（可用时）和 PoC-A 完成“首次可接受 PDF”。每条路径独立计时，预先采用同一合格标准，不复用另一工具已排好的文件。记录：总时间、纯手工排版时间、格式调整次数、未解决页面问题、PDF 页数和是否愿意实际发送。熟悉效应通过交替顺序或间隔执行降低；软件完整版本和机器环境入表。

具体开始/停止计时、调整次数、停表检查和证据保存口径见 `docs/poc-a/人工基线执行手册.md`。该手册只操作化既有标准，不构成事后修改实验条件。

`BASE-01` 实际运行 122.3 分钟后仍未产生愿意发送的成品，属于右删失观察：人工首次可接受 PDF 总时间只可记为“大于 122.3 分钟”，不得把业主约 3 小时的估计当作实测。业主批准不再继续或重跑该长文人工基线；Word 按决策 #2 延期。

PoC-A 工程门槛：在不降低本说明任何 PDF 合格标准的前提下，首次可接受 PDF 总时间不超过 60 分钟，全程人工排版/干预不超过 20 分钟。该绝对门槛替代无法从右删失试跑准确计算的个人“手工排版下降 60%”指标。阶段 2 的 20–30 名真实用户验证仍使用每名用户自己的完整 WPS/Word 对照与原有相对指标，本修订不改变产品级成功定义。

## 通过、失败与处置

- **通过**：全部 PDF 合格标准、故障检出门槛和对照时间门槛同时满足，且实现没有逐页特例或针对 fixture 写死内容位置。
- **有条件通过**：桌面 Chromium/Electron 达标，但 ArkWeb 存在可隔离兼容差异；记录差异和后续壳策略，不阻断桌面首战。
- **失败**：廉价路径无法稳定控制目录/分页/表格图片/字体，自动检查无法可靠发现 P0，或大部分时间仍需逐页手调。
- **失败处置**：停止扩展排版功能；先判断能否通过受控布局层补足。仍触顶则执行冻结纲领的“轻排版”降级，重新审查产品入口；不得为证明原路线正确而事后更换样本或放宽标准。
