# ADR-0018：PB-05 可定位 diff 与裁决边界

- 日期：2026-07-29
- 状态：已实现，待 Claude 独立审计
- 决策：AI 候选先在隔离 preview 事务中生成字段级差异；只有显式接受的单项候选才经
  PB-04 gateway 和 PB-03 事务写入权威文档。

## 决策

1. `DiffReview.propose` 从权威 manager snapshot 克隆 preview manager。候选工具在 preview
   内走同一 PB-04 gateway；preview 永不替换权威 manager snapshot。无效候选只形成
   rejected 提案，不产生 diff 或写入。
2. diff 以稳定 `nodeId + field` 表达。每条含 `parentId`、祖先 ID 链和 sibling index；
   移动表达为 `$parent` 字段变更。新增/删除逐字段记录，禁止以「整块已替换」伪装局部
   变化。
3. 每一个 PB-04 工具调用是一项独立的候选，可分别 pending、accept 或 reject。accept
   重新调用权威 PB-04 gateway，最终仍由 PB-03 校验/提交/回滚；reject 只改变提案状态。
4. 最近一次已接受候选可调用 `undoAccepted`，其唯一写动作是 PB-03 manager 的 `undo`；
   不复制、重放或篡改文档。PB-05 不实现多人合并、UI、存储或新写路径。

## 后果

- AI/模型在本任务仍为契约输入；没有 provider、自动接受或多人合并 UI。
- 部分接受适用于互不依赖的候选。依赖候选若因先前 reject/accept 导致权威 PB-04 操作
  无法提交，则如实返回 transaction rollback，不猜测或静默重写。
- 新包只引用现有 workspace 包，供应链重建仍是唯一 SBOM 真源。
