# ADR-0010：PA-11A 目录页码两遍渲染测量与页眉页脚压印受控补偿

- 日期：2026-07-28
- 状态：已接受（实施决策，随 PA-11A 独立审计复核）
- 关联：路线图 PA-11 行（目录与页码忠实）、ADR-0004（Host 能力边界）、ADR-0007（诚实门先例）、PA-05（签署基线管线）、PA-11A 开工指令

## 背景

PA-11 分域要求目录条目页码与实际分页严格一致（标题-目录对应），且
页脚页码「N / total」真实反映物理分页。两个先决事实在实施期探针
实测定案（留痕于实施记录）：

1. **Chromium 能力触顶**：`target-counter()` 与 `@page` 页边盒
   （`@top-left` 等）在 Chromium 150（签署环境 Edge 150.0.4078.83 与
   开发环境 Chrome 150.0.7871.187 双端实测）不受支持——CSS 无法让
   目录条目获得实际页码，也无法让浏览器原生渲染页眉页脚文本。
   这是冻结工具链的能力边界，不是实现选择。
2. **结构事实可得**：`printToPDF` 的 `generateDocumentOutline`（PA-05
   已冻结为 true）产出书签大纲，每项携带标题文本与显式
   `/Dest [pageObj /XYZ …]`——浏览器自己声明的物理页锚定，非几何
   启发式。

由此产生两个设计问题：页码从哪来（禁手写、禁猜测）；页眉页脚怎么
进入 PDF（能力触顶后的补偿如何保持受控）。

## 决策

### 1. 目录页码：两遍渲染 + 大纲测量 + 不动点收敛

- 第一遍：目录条目页码占位为空渲染，从产物大纲测量每个条目锚定
  章节的**实测物理页码**（pageIndex+1，封面=1）。
- 大纲-条目对位用**文档序游标**：目录条目按文档序逐一消费大纲项，
  同文标题（封面题名双现等）由游标顺序消歧；条目不匹配、缺大纲、
  非 `/XYZ` Dest、Dest 指向未知页对象——一律 fail-closed，绝不
  猜测页码。
- 第二遍：把实测页码填充进占位（每条目占位必须恰好出现一次，防
  静默错位），重渲染后**重测页码集合**：与填充值一致即收敛（实测
  签署基线一轮收敛）；不一致则以重测值再渲染，**上限 3 轮**，超限
  fail-closed（`PDF_EXPORT_PAGINATION_FAILED`）。收敛逻辑为纯函数
  `resolveStableTocPages`（不触浏览器），轮数上限/收敛判定/反馈
  游标均可决定性变异。
- 页码语义钉定：页码 = 物理页码（封面计入），页脚格式
  `N / total`——与读者翻阅事实一致，不发明逻辑页码体系。

### 2. 页眉页脚：PDF 层压印（受控补偿），不进 HTML

能力触顶后不在 HTML 层伪造（fixed 定位页眉会随内容流漂移、与分页
事实脱钩），改在打印产物上以**增量更新压印**（原字节前缀不变，
与 PA-05 修复层同机制）。受控性来源：

- **字形零新增**：压印字符逐字复刻引擎自身产物——优先已内嵌子集
  字体的 ToUnicode 单字符映射（部首码位归一后等价视同同字）；
  无单字符映射的字（如「文」）复刻检查器 origins 记录的引擎原
  表示（同字体对象、同字形码、ActualText 单字标注）；两路均无即
  fail-closed（宁缺印，不虚构）。
- **位置公式唯一**：页眉/页脚基线钉在模板上/下边距带内
  （`height − marginTop/2 − 0.35·size`、`marginBottom/2 − 0.35·size`），
  x = 模板左边距，9pt 常量——全部由冻结模板边距派生，不逐页写死。
- **零交叠自检**：压印带与既有文本 run 包围盒相交即
  `PDF_EXPORT_STAMP_FAILED`（几何事实，非阈值发明），先于任何
  字节改写。
- **封面豁免**：物理第 1 页不压印。
- **压印后自核验**：终稿重新提取，逐页确认页眉+页脚串以提取序
  后缀精确出现（归一口径），位置锚定剥离后再走 PA-05 逐字对账——
  压印未生效或错位不能静默放过。
- **多 tag 字体登记**：压印在页资源增补统一新 tag（`PA11F<n>`）
  引用既有字体对象；检查器与几何解析按「同一字体对象多 tag」
  登记（开发期实测单 tag 登记会造成 2577 字形洞/9312 字符丢失，
  已转为决定性变异用例）。

### 3. 协同重签与契约级联

- 页码/页眉页脚改变分页与文本层（20→21 页，目录页独立成页），
  签署基线 PDF 按签署协议在 Win11 参考 VM（Edg/150.0.4078.83）
  重签，两次导出剥离 CreationDate/ModDate 时间戳后 normalized
  sha 完全一致（原始字节含元数据政策允许的时间戳差异，确定性
  判定以 normalized 口径留证），过 PA-05 级验证链；
  下游锚点（pdf-evidence/report-checks 基线钉、页码、figure/
  表格页位）全部探针重测刷新，禁止从旧值推猜。
- 文档契约 additive 升 **0.2.0**（`toc` 块入 Block oneOf），冻结
  0.1.0 schema 保留，reader 双版本分发（PA-06B 先例）；markdown
  导入 `[[TOC]]` 标记产 toc 块；渲染为 `<nav class="toc">`（收录
  level 1–2、排除封面同文题名子树，规则唯一归口 document-model
  `collectTocEntries`，render 与 checks 共用）。
- 零新增第三方运行时依赖。

## 备选与拒绝理由

- **CSS target-counter/页边盒**：Chromium 不支持（触顶实测），
  排除。
- **HTML fixed 定位页眉页脚**：位置随内容流漂移、与物理分页脱钩，
  且与 PA-04 白名单 CSS 能力不符，排除。
- **手写/模板声明页码**：违反「页码派生自实际渲染」门禁，排除。
- **压印使用新嵌入字体**：引入非冻结字形、破坏字体纯冻结 OTF
  子集口径，排除（逐字复刻策略代之）。
- **几何启发式测页码**（按标题 run y 位置估页）：大纲 /Dest 是
  浏览器结构事实，严格更强，排除。

## 后果

- pdf-export 管线变为「两遍渲染（≤3 轮不动点）→ 文本层修复 →
  压印 → 终稿自核验对账」，失败码新增
  `PDF_EXPORT_PAGINATION_FAILED` / `PDF_EXPORT_STAMP_FAILED`。
- 签署基线结构变化：21 页、目录独立成页（p3）、p2–p21 带页眉
  页脚（封面豁免）——下游所有页位钉随重签刷新。
- 已知承接：PA-11B 在其上做目录-正文双向对账、页眉页脚一致性
  与实际页码红线检查；人工核验项（PA-08/09/10 登记）不因页码
  变化免除。
