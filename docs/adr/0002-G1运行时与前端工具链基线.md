# ADR-0002：G1 运行时与前端工具链基线

- 日期：2026-07-20
- 状态：已接受（G1-02）
- 关联：`G1-02`、`G1-03`、`G1-03C`、`G1-08`、`G1-11`、`G1-12`
- 机器可读真源：`toolchain.versions.json`

## 背景

项目进入工程底座阶段，需要先冻结可复现、免费且许可证可接受的运行时和前端工具链，再建立工作区。版本选择必须区分开发机 Node 与 Electron 内嵌 Node，避免把“当前最新版”当作可重现约束，也不能在 TypeScript 生态迁移期盲目采用尚未满足本项目工具集成要求的新主版本。

## 决策

| 组件 | 冻结版本 | 许可证 | 选择理由 |
|---|---:|---|---|
| Node.js | 24.17.0 LTS（Krypton） | MIT | LTS 线；不采用尚未进入 LTS 的 Node 26 |
| pnpm | 11.15.1 | MIT | 2026-07-20 官方注册表稳定版；后续通过 `packageManager` 精确锁定 |
| TypeScript | 6.0.3 | Apache-2.0 | 保留成熟的编程式 API 与工具生态兼容性；暂不采用 7.0 原生移植线 |
| Vite | 8.1.5 | MIT | 当前受支持的稳定补丁版 |
| Electron | 43.1.1 | MIT | 当前稳定线；内嵌 Chromium 150.0.7871.114、Node 24.18.0 |

执行规则：

1. `toolchain.versions.json` 是精确版本、下载来源与完整性值的机器可读真源；G1-03 创建 `package.json` 时必须与其一致，不使用 `latest`、宽泛主版本或浮动范围。
2. Node 安装包只从 `nodejs.org` 获取并核验官方 `SHASUMS256.txt`；npm 包只从官方 npm registry 获取，并由 lockfile 校验其 `integrity`。
3. 开发机 Node 24.17.0 与 Electron 内嵌 Node 24.18.0 是两套运行时。主进程、preload 和渲染器的兼容结论必须在 Electron 环境复验，不能用开发机 Node 通过替代。
4. Windows 10 开发机可用于 G1 建设；PoC-A 的正式主判定仍以路线图指定的 Windows 11 参考环境为准。路径、大小写、字体、DPI 和 Chromium 输出差异必须留证。
5. DevEco Studio、HarmonyOS SDK 与 ArkWeb 版本由 G1-12 使用华为官方当前稳定发布另行登记；不得根据本 ADR 猜测版本。
6. 依赖升级必须是独立变更：更新版本真源和 lockfile，运行完整 `verify`、真实渲染回归、Electron 安全检查及许可证/漏洞审计。Electron 或 Chromium 主版本升级须新 ADR。

## TypeScript 7 延后条件

TypeScript 7.0 已发布，但官方说明其稳定编程式 API 要到 7.1 才提供，部分生态工具仍需 TypeScript 6。满足以下条件后才评估升级：

- TypeScript 至少达到 7.1 稳定版；
- Vite、lint、类型生成、测试与编辑器插件均明确支持；
- 严格类型检查、构建和生成漂移检查全部通过；
- 不需要长期维护两套 TypeScript 编译链。

## 结果与撤销条件

- G1-03 可以在明确版本上建立可复现工作区。
- 当前直接候选许可证均符合项目允许范围，未引入 GPL/AGPL。
- 若官方撤回版本、出现高危漏洞、许可证改变或下游无法兼容，则停止消费该版本，记录替代版本与验证证据；不得静默修改版本文件。
