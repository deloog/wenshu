# ADR-0004：v0 项目、知识包与语义审计边界

- 日期：2026-07-20
- 状态：提议（G1-07 首审失败，整改待独立复审）
- 关联：宪法 3/5/8/9/15、R-DATA/R-RECORDS/R-OUTPUT

## 背景

文枢需要本地项目、可迁移知识包、正式版本与可问责的语义审计，但数据库、编辑内核和 CRDT 尚未选定。如果此时把存储表结构或编辑操作日志当作交换格式，会让产品真源依赖未验证实现，并混淆真源、派生和三层记录。

## 决策

1. 用平台与数据库中立的 JSON 契约描述项目清单、知识包 manifest、语义审计事件和兼容策略，版本统一从 `0.1.0` 起步。
2. 项目清单以稳定 ID、版本和 SHA-256 引用文档、模板、材料、审计与正式版本，不复制正文或绑定数据库主键。
3. 知识包 entry 必须区分 `truth.*` 与 `derived.*`；真源必需且不可重建，派生物非必需且必须可重建。凭证、诊断日志和模型原始内容不属于知识包真源。
4. 语义审计只记录责任事件、出处、前后哈希和最小模型元数据；actor 是作出动作的用户或受限系统行为，模型来源作为被裁决对象的 `subject_model_context` 独立记录。AI 修改接受/拒绝和正式版本批准只能归属于用户，action/decision/节点/哈希必须满足可执行一致性规则。编辑器事务与 CRDT 合并记录使用各自独立结构。
5. 未知版本拒绝；任何行为变化使用显式 adapter；破坏性变化升级主版本并写 ADR；产生真实数据后保留旧 Schema 与迁移链。
6. 项目契约直接互锁 document/template 的导出版本与联合 fixture；上游版本或 ID 规则变化必须让本包门禁失败并显式升级。
7. v0 不实现迁移路径、数据库或压缩包 IO。真实知识包重导入、哈希和路径安全由 PB-11 在真实文件系统验证，真实迁移由 PB-09 在选定的生产同类数据库验证。

## 结果

- 存储候选可以改变而不改变用户可迁移真源的语义。
- 完整知识包可以对账内容、模板、材料、审计和正式版本，派生索引可删除重建。
- 审计记录保持可问责但不沉积正文、prompt、密钥和高频编辑噪声。
- 后续若无法从真实存储无损构造本契约，必须回到 ADR 审查，不能缩减知识包承诺。

## 升级条件

出现新增真源类别、同步协议、正式版本无法由文档+模板+审计重现、迁移需要改变历史语义，或隐私审查要求改变审计字段时，必须升级契约、补兼容/迁移说明并重跑消费者与干净导入测试。
