# ADR-0014：增量分页是待建架构能力，不是已证明的 Chromium 修复

- 日期：2026-07-29
- 状态：建议，待业主批准
- 关联：PA-13、DEGRADE、[增量分页可行性探针](../pagination-incremental-evaluation.md)

## 决策建议

不改变 8 秒全量预算，也不宣布 1 秒局部预算通过。现有 Chromium 导出链只提供完整文档两遍打印；真实探针显示局部、早中晚编辑均走完整管线。

建议把“可交互局部更新”登记为 PB/Alpha 必须建设并实测的架构能力：受影响区计算、稳定页缓存、后台可取消任务和旧预览协调。此建议不等于允许直接实现，也不改变 PB/Alpha 的排版依赖冻结。

全量分页仍是独立 `not_met`：PA-13 参考 VM p95 24.300 秒 / 8 秒。增量架构即使未来成立，也不能追认全量预算为通过。

## 必须由真实编辑器验证的项目

- 旧预览在后台任务期间保持可操作；
- 局部编辑到受影响页更新的端到端 p95；
- 全量重排取消时的 UI 反馈、资源清理与主线程不阻塞；
- 分页级联、目录/页码更新和缓存失效在参考 VM 的十次确定性与正确性对账。
