# ADR-0012：PA-12 汇总闸门报告契约与门槛诚实性口径

- 日期：2026-07-28
- 状态：已接受（实施决策，随 PA-12 独立审计复核）
- 关联：路线图 PA-12 行、ADR-0007（诚实门）、ADR-0008/0009/0011（严重级证成先例）、PA-07~11B 审计报告与 followups 台账、PA-12 开工指令

## 背景

PA-12 是 PoC-A 汇总闸门：validator runner 对正常样本（签署基线）+ 12
个故障样本跑全检查族（P0: PA-07；P1: PA-08/09/10/11B），产出版本化
门禁报告（汇总 findings + 人工清单 + 门槛评估 + pass/fail 裁定）。四
个设计问题须书面证成：fault 样本的派生层选型、门槛计数口径、豁免机
制形态、门禁报告如何防「自报说谎」。

## 决策

### 1. fault 样本：证据层确定性内存派生（与 PA-07~11B 审计惯例同源）

12 个 fault 样本自签署基线证据（sha256 锚定
`5d7c06bc…0828`）`structuredClone` 后注入缺陷，不改任何冻结物、不产
出 committed fault PDF。理由：

- 与 PA-07/08/09/10/11B 已签署审计的 fault 注入模式完全一致——每个
  注入的锚点（归属 run、表格结构、压印 run、目录配对）都来自已审计
  过的真实分析路径，锚点缺失即 `GATE_FAULT_ANCHOR` fail-closed；
- 路线图层 `docs/poc-a/fixtures/fault-cases.json` 的 12 例是文档级变
  异描述（需重导出 PDF），属 PA-05 管线域；PA-12 的验收对象是「检查
  族对缺陷证据的检出能力」，证据层派生恰好隔离该变量且确定性可复算；
- 覆盖域按开工指令逐域一例、不重复充数：P0 尺寸/越界/遮挡/内容 ×4，
  P1 标题/孤行/寡行/留白/表格/图片/目录页码/页脚页码 ×8；PA-K1（图
  遮正文）落 PA-07 检出域（fault-p0-overlap，成员制 paintBBox 判据），
  PA-11A 实际页码红线由 fault-p1-toc-page-mismatch 承接（跨页 fault
  保持归属完整，PA-N1 已审定语义）。

### 2. 门槛计数口径：检出只计 findings，逐样本布尔判定

- fault 样本 `detected` === 每个期望码都出现在该样本**真实 findings**
  （码级匹配）；manualChecks 永不满足检出（命名空间隔离：`*_REVIEW`
  人工码段与自动码不串，契约语义重算双重兜底）。
- 门槛三量全部从真实产出重算：P0 检出率（未全检出即 FAIL，
  `GATE_P0_MISSED`）、P0+P1 检出数 ≥ 10/12
  （`GATE_DETECTION_BELOW_THRESHOLD`）、正常样本误报 ≤ 2
  （`GATE_FALSE_POSITIVE_OVERFLOW`，误报 === 正常样本 findings 数，
  不得隐藏/重分类）。
- 门槛常量（12/10/2）在门禁报告 schema 中以 `const` 钉死——调低门
  槛必须升契约版本，类型层同步钉死。
- 样本集不全（fault 数 < 12）天然不达标：检出数上界随样本数缩，
  无法靠挑样本/减样本凑过。

### 3. 豁免机制：P1 单条豁免 + 理由记录 + P0 双重拒绝

- 豁免输入类型级限定 `P1RuleId`；运行时对不可信输入逐条复核，任何
  P0 豁免尝试抛 `GATE_P0_EXEMPTION_REJECTED`（fail-closed，不产报告）。
- P1 豁免的表达 = 该规则从 `executedRules` 缺席（复用 PA-07 已审计的
  单规则禁用回滚机制），报告 `exemptions` 逐条记录理由；豁免代价如
  实计入检出统计（对应 fault 检出丢失，检出数下降，绝不伪装）。
- 门禁报告契约语义层双重禁止 P0 豁免出现在报告中。

### 4. 门禁报告防说谎：读者全量重算（不信任何自报数字）

`validateGateReport` 在 ajv 结构校验后做语义重算：逐样本
`detected`/`falsePositives` 从 findings 重算、`evaluation` 五个计数 +
`p0DetectionRate` + `verdict`/`failureCodes` 全量重算、`executedRules`
必须等于「全规则集 − 已申报豁免」（防选择性跳过）、样本
findings/manualChecks 的 ruleId 必须属于已执行规则集。runner 产出先
过自身契约（fail-closed `GATE_INTERNAL`），审计方可独立重放
（`scripts/run-gate-baseline.ts`）再过 reader 交叉验证。

### 5. 人工清单：静态承接登记 + 动态钉数

PA-A7/J1/K1/L1~L4/M1~M5/N1/N2 逐项登记 disposition
（carried/registered/closed/external）+ 权威文档引用；PA-J1/M1/N2 的
`relatedCount` 由 runner 以正常样本真实 manualChecks 总数（33）动态
填充，不手写。清单显式列出供人工核验，绝不并入自动检出统计。

## 后果

- 闸门诚实性命门有四重独立防线：码命名空间隔离、runner 自检契约、
  reader 全量重算、变异测试五连红。
- 已知边界（如实登记）：fault 注入为证据层派生，不覆盖「渲染管线产
  生缺陷 PDF」的端到端路径（该路径由 PA-14E/14H 壳复验承接）；文档
  级 fault-cases.json 的 12 例与样本库覆盖域同构但实现层不同，映射
  关系在实施记录书面化。
