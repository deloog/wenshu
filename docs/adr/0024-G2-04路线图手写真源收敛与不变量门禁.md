# ADR-0024：G2-04 路线图手写真源收敛与不变量门禁

> 状态：已生效（随 G2-04 实施）　日期：2026-07-30
> 依据：[任务书 r3](../audits/roadmap-invariants-gate-task.md)（业主批准，实施者两轮独立审计后定版）；本 ADR 为任务书 §0.2 的强制交付物。

## 背景

`docs/implementation-roadmap.md` 是 GR 已通过文档。其同一套关系（任务依赖、`R-*` 归属、完成状态与证据）此前在**五处并列手写**：任务表"依赖 → 消费者"列、§3 关键路径 ASCII、§9 并行波次、§10 双向追踪矩阵、§3.1 执行台账。互不校验的结果是任务书 §2 实测的四类失修：台账再次过期（且过期的就是刚签署的上一个治理任务 `G2-03` 自己）、§3 三条边与依赖列矛盾、§9 五个"可并行组"内含任务与其直接依赖、四处消费者声明在依赖链中不存在。r1 审计另证实：依赖列里一个拼错的 ID（`PB-O9`）会被提取正则静默丢弃，形成环检测与一致性检查全部绕过的静默断链。

本任务改变的是这份 GR 已通过文档的**维护方式**，按 §11"核心架构……变化：写 ADR，更新消费者依赖并重审"的要求立此 ADR。

## 决定

1. **三类权威手写源**：§4~§8 任务表的依赖列（直接依赖）、任务的 `R-*` 标注、§3.1 台账的状态字段与证据链接。语义已写入路线图 §11。
2. **四处派生校验对象，不再视为并列真源**：
   - §3 关键路径：阶段主干的**编辑性摘要**，箭头表示"直接或传递前置"；每条边须在依赖列中有传递依赖依据。**不生成**——"哪条链是关键路径"是人的编辑判断，不是图的输出，生成会毁掉编辑意图。
   - §9 并行波次：**任务级**可并行组，组内不得含任务与其直接依赖。W1 为历史组（散文限定词表达阶段级并行，不可机械判定，任务已全部完成），显式登记豁免，不追溯改写；此后新增波次须使用可判定格式。
   - 消费者列：真实传递下游的**子集**，不要求完备。取"子集"而非"互为逆"是刻意取舍：互为逆需修 131 处且大量落在已签署行上；子集约束只需修 4 处，仍能抓住真正的错误（声明依赖链中不存在的下游）。
   - §10 矩阵：**编辑性覆盖摘要**（任务书 §2.5 裁定），不是派生索引；主责/贡献性参与的归属是编辑判断，门禁只校验其中任务 ID 的存在性与 `R-*` 覆盖，不做双向归属对账。该声明已写入 §10 本文。
3. **机械门禁**：新增 `tools/quality` 路线图不变量检查器（解析 / 检查 / 报告分模块），执行 10 条判定（基础检查 1~7 + 检查 8 的子检查 8a/8b/8c），接入 `pnpm verify`（经 `quality:check`）与 CI `static` job，不新增 job、不改并行矩阵结构。
4. **解析 fail-closed**：检查器输出六项解析计数并对照登记下限（任务 77 / 依赖边 238 / `R-*` 18 / 台账 49 / §3 边 23 / §9 组 12，允许向上增长）；低于下限即失败，未能解析的表格行逐条报错，不静默跳过。"跑过了"不等于"检查过了"。
5. **例外只在三张显式登记表中，且 fail-closed**：已批准偏离（`PA-15`/`PA-14U`，决策 C）、8a 审计报告例外（11 条穷尽列举）、8b 无独立报告豁免（6 条穷尽列举）、历史波次（W1）。登记表是单一手写真源（`roadmap-registry.ts`），检查器只读它；登记项与现状不符（失效豁免、缺失文件、偏离不再成立）本身即失败。
6. **8a 与 8b 是相反方向，并存而非二选一**：8a 抓"审计完成却没进台账"，8b 抓"台账声称完成却不指向自己的证据"（宪法 21）。8b 的别名映射从 8a 例外表的 `countsAsTaskReportFor` 派生，不另抄一份。

## 考虑的替代方案

- **收敛为单一手写真源**：r0 曾提"一处"，与任务实际需要（依赖、`R-*`、完成状态语义不同源）矛盾，r1 已更正为三类。
- **要求 §10 与任务标注双向一致**：会在已签署行上制造 64 处归属编辑，而路线图从未定义归属口径；不成比例且动已签署证据。裁定为编辑性摘要（任务书 §2.5）。
- **生成 §3 关键路径**：见上，拒绝。
- **引入 markdown 解析库**：零新增第三方依赖是任务书硬约束；表格结构简单且必须 fail-closed，自写 60 行表格助手更可审。

## 后果

- 台账过期、关键路径与依赖列矛盾、波次含直接依赖、消费者断链、ID 拼断链、台账行无证据链接，由人工发现变为 CI 拦截。
- 现存 31 处违反全部关闭：检查 5/6/7 的 12 处文档修正、`G2-03` 台账条目补录、8b 的 17 行纯追加链接、`PA-15`/`PA-14U` 经已批准偏离登记表显式豁免。
- 路线图版本升至 1.5；§9/§10/§11 写入了语义与地位声明。
- 本门禁**不校验**路线图内容的正确性（某任务是否真该依赖某任务），只校验记载间一致性与结构不变量；§10 的 64 处归属不一致明确不修。

## 局部重审说明

本 ADR 改变的是文档维护方式，不改变任何任务的范围、依赖语义或验收口径：31 处修正中 17 处为纯追加链接、12 处为被检查判定为错的派生字段（§3 边、§9 组、消费者列）、1 处为台账补录、1 处为例外登记；未改动任何已签署任务行的实质内容，未重排既有台账。判定**不需要**对既有任务做局部重审；门禁本身经 29 条反例矩阵（含 11 条防误报反向反例）逐条独立复跑验证，最终由 Claude 独立审计签署。

## 增补（2026-07-30，审计 MI-01 关闭）

**裁定：`G1-09` 确实依赖 `G1-06`。** G2-04 实施按「消费者列=派生校验对象、依赖列=权威手写源」删除了 `G1-06` 消费者列中的 `G1-09`（该声明在依赖链中不存在）；独立审计（MI-01）指出此删除抹掉了一条真实依赖在路线图中的最后结构性记载。证据：`G1-09` 任务行散文自证——范围内含「处理 Host 复审 NF-02」、完成证据含「Host 值拒绝 NUL/控制字符及带任意前缀的盘符、POSIX/UNC、`file:` 和穿越片段」，二者均为 `G1-06` Host 契约的产物；且 `G1-09` 行明示「Host NF-02 必须在 PA-14E/PB-10 等真实 Host 消费协议值前经独立审计关闭」。据此修正权威手写源：`G1-09` 依赖列补入 `G1-06`（`G1-03 → 全任务` 改 `G1-03/06 → 全任务`），`G1-06` 消费者列恢复 `G1-09`（路线图 v1.6，依赖边 238→239，高于登记下限）。其余三处删除（`G1-03C → G1-08`、`A-01 → A-07P`、`A-02D → A-03`）经审计逐处核散文未见同等证据，维持删除。已签署任务行的范围、证据、验收口径文字均未改动，仅补回一条被漏记的依赖边与其逆向消费者声明，不构成实质内容变更。

**新增维护规则（冲突先裁定）**：此后消费者列与依赖列冲突时，若任务行散文（范围、完成证据、验收口径）存在任一侧为真的证据，须先裁定哪一侧为真并记录理由，再决定改依赖列还是消费者列；不得默认删除派生侧。门禁语义不变——消费者列仍是派生校验对象、不要求完备——但「子集不合规」只是冲突信号，不等于「消费者声明为假」。该规则源于任务书规格未预见的情形，审计已将过失归因于起草方；规则在此立据，后续路线图维护（含门禁检查 7 发现处置）一体适用。
