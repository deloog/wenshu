# ADR-0026：PB-11 知识包导出与干净环境重导入

- 日期：2026-07-31
- 状态：已实现，待 Claude 独立审计
- 决定：在 `@wenshu/knowledge-package`（L2）实现知识包 ZIP 容器、canonical
  序列化、字节级 SHA-256 校验与事务化导入；不扩展 Host payload schema，
  读写以已授权 grant 目录为边界；闭合 G1-07 m-01。

## 决策依据

### 1. 容器格式：自写最小 ZIP，零新增第三方运行时依赖

- 项目纪律（PA-06~12、PB-09、PB-10）要求核心路径不引入第三方打包/压缩库，
  避免触发新的许可证、SBOM 与 lockfile 审批。
- `node:zlib` 提供 `deflateRawSync`、`inflateRawSync` 与 `crc32`，足够实现
  STORE/DEFLATE 两种方法的最小 ZIP 读写；路径使用 UTF-8（general purpose bit 11）。
- 路径检查在 ZIP 读写两层都执行：拒绝绝对路径、反斜杠、`..`/`.` 段与空段，
  fail-closed。

### 2. 序列化与哈希口径

- 所有 JSON 真源对象使用同一 canonical 序列化：按字典序递归排序对象键，数组保持顺序，
  紧凑无尾随换行，UTF-8 编码。
- 语义审计流使用 NDJSON：每条事件一行 canonical JSON，末尾带 `\n`；
  `truth.audit` 的 SHA-256 覆盖整份 NDJSON 字节。
- `truth.project`、`truth.audit`、`truth.document`、`truth.template`、
  `truth.material` 的哈希**全部从真实序列化字节计算**，不再沿用 manifest 自报值。

### 3. 闭合 G1-07 m-01

G1-07 审计原文指出：`truth.project` 与 `truth.audit` 两个 entry 的 sha256
“从不被任何校验消费”。PB-11 是其唯一关闭点：

- 导出时 `exportKnowledgePackage` 先 canonical 序列化项目清单与审计流，再计算 SHA-256，
  最后写入 manifest。
- 导入时 `importKnowledgePackage` 逐 entry 读取 ZIP 中的真实字节，重新计算 SHA-256，
  与 manifest 声明比对；任一真源字节改动即 `PACKAGE_HASH_MISMATCH`。
- `validateKnowledgeBundle` 继续承担项目/审计/manifest 之间的交叉引用校验，
  两者不互相替代。

### 4. 与 Host 边界的关系

- 不新增 `file.read` 或 `file.import.select` 等 Host payload 能力；PB-11 的 API
  直接接收已授权目录（grant root）与 ZIP 文件路径，在 L2 内完成读写。
- 理由：目录授权与权限提示仍由 Host 的 `project.directory.select` 承担；
  PB-11 只负责“目录已授权之后的格式与字节完整性”。
- A-02/A-11 的收口方式：Host 选择/授权目录后，将 grant root 传入
  `@wenshu/knowledge-package` 的导出/导入 API；导入完成后，材料原件在
  `grant.protectedFiles` 中登记，防止后续 `file.export.write` 误覆盖。

### 5. 事务回滚与干净环境

- 导入先解压到与目标目录同卷的临时目录（`<targetRoot>.wenshu-import-<uuid>`），
  完成全部哈希校验与 bundle 校验后，才 `rename` 为最终目录。
- 任何失败都删除临时目录；目标目录要么完整出现，要么不存在，不留半包。
- 集成测试包含“新进程”用例：父进程导出 ZIP，子进程（独立 Node 实例）导入并校验身份。

### 6. 真源/派生分离

- 派生 entry 在 manifest 中 `required: false`、`rebuildable: true`；
  导入时若派生文件缺失，只要 manifest 中移除对应 entry，包仍可成立。
- 测试中验证：删除派生文件与 manifest 条目后，round-trip 仍然成功。

## 未选择与后续

- docx/Markdown 导出、ArkWeb 真机验证、A-11 项目列表/搜索 UI 不在 PB-11 范围内。
- 多版本正式版本（`formal_versions` 非空）的历史文档/模板打包待未来需求明确后扩展。
- 当前实现要求导入目标目录事先不存在；覆盖/合并策略由 A-02/A-11 在 Host 层决策。
