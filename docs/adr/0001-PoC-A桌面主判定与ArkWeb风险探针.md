# ADR-0001：PoC-A 以桌面 Chromium/Electron 为主判定，ArkWeb 为跨端风险探针

- 日期：2026-07-20
- 状态：已接受（G0，2026-07-20）
- 关联：冻结纲领 §五“排版与版式引擎”、§六“PoC 双闸门”

## 背景

冻结纲领同时要求 PoC-A 验证字体与跨端输出一致性，并把 DevEco 薄壳搭建列入 PoC-B。若不解释时序，可能出现两种错误：要么在排版价值尚未成立前投入完整鸿蒙壳；要么把 ArkWeb 风险完全推迟，直到桌面架构难以调整。

## 决策

1. PoC-A 的生死主判定环境为固定 Chromium，并在 Electron 中复验；它对应首个正式生产环境和主要用户验证环境。
2. GR 通过后，在 G1 安装并锁定 DevEco Studio、Command Line Tools 和 SDK，建立只含 ArkWeb 与 host 桥接的最薄壳。
3. ArkWeb 使用与桌面相同的 fixture、模板和字体做页数、换行、fallback、几何与能力差异探针，不要求 PoC-A 阶段像素级一致。
4. 桌面达标而 ArkWeb 存在可隔离差异时，PoC-A 可“有条件通过”；差异必须记录并限制鸿蒙端承诺。若 ArkWeb 缺陷暴露 Web 核心或模板协议不可移植，则作为阻断问题处理。
5. ArkWeb 薄壳不得承载业务逻辑，不得为了追求页面一致而复制一套鸿蒙专属文档模型。

## 结果

- 排版生死判断不会被 IDE/壳工程工作量污染。
- 跨端风险仍在架构定型前暴露。
- 鸿蒙首期可以根据探针结果承担查看、捕获或轻编辑等合适职责，交付级导出仍以桌面能力为准，直到鸿蒙单独通过发布闸门。

## 撤销条件

- 用户验证证明鸿蒙端是首个正式生产环境；或
- ArkWeb 提供经实测可直接满足同等交付级导出的稳定管线；或
- 冻结纲领因 PoC 双闸结果正式重启修订。
