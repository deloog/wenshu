## 1. 背景与事实基线（全部为已签署/已审计事实）

1. **②「局部编辑后相关页面更新 ≤ 1 秒」永久登记未达成**（决策 #27 D1）：CDP printToPdf 架构下 VM 实测 p95=4370.7ms（n=30，超限 4.37×）；任何方向的环境修正均不改变结论方向（审计者独立压测：翻转需 −77.1% 修正，实测漂移仅 −12.3%）。**台账不得追认。**
2. **架构地板已实测**：VM 两点线性分解——固定成本 ≈509ms + 边际 ≈501ms/页；最小 2 页窗 print 也含整份 print-layout 固定成本，1s 物理不可达。
3. **取消域已闭合**：P6 取消 target 隔离落地（决策 #27 D3），run-p6-3 判定器 G7 逐轮 settleAfterClickMs ≤ 2000 达成（10/10 ∈ [4.9, 868.6]ms）——「可取消、旧预览不消失」的工程基础就位。
4. **P4 双层预览与冻结 UX 契约兼容**（决策 #27 D2 已核）：G0 失败处理列「允许显示正在重新分页，旧预览不消失」；ux-state 冻结契约 `stalePreviewRetained: const true`、`repaginationScope: const "incremental"`（states-1.0.0 pagination 行）。
5. **否决路径已裁定**：「把 ≤1s 重新解释为 HTML 层反馈」被决策 #27 D1 否决——层 1 不含真实分页，不构成「页面更新」，是重定义而非澄清。本修订**不重解释既有行**，而是**新增两条分别命名的预算**并让原行永久挂 not_met。

## 2. 修订内容（additive，既有行一字不改）

`docs/performance-budgets.md` §参考任务预算**新增两行**，原「局部编辑后相关页面更新 ≤ 1 秒」行**保留原文**，仅追加状态标注「（永久 not_met：决策 #27 D1，p95=4370.7ms，不追认）」：

| 指标（新命名） | 目标 | 测量对象与口径 | 失败处理 |
|---|---:|---|---|
| **局部编辑交互反馈（HTML 预览层）** | p95 ≤ 1 秒 | 编辑提交 → 层 1 HTML 预览完成更新（含结构/文本回流，**不含真实分页与 print**）；30 页首战上限语料、参考 VM、判定器逐轮留证 p95 判定 | 超过即分析；不得冻结编辑、旧预览不消失 |
| **局部编辑页槽精确更新（PDF 预览层）** | p95 ≤ **X 秒**（业主裁定值，见 §3） | 编辑提交 → 受影响页槽 PDF 精确更新完成（含真实分页、目录页码、增量↔整份等价对账）；后台异步执行，不阻塞编辑与旧预览；30 页语料、参考 VM、p95（nearest-rank，n≥30） | 超时须保持旧预览有效并可取消（P6 形态）；退化超 20% 按回归规则阻断 |

§稳定性预算、§输入护栏、§回归规则**一字不改**；「取消后 2 秒内停止消耗」等全部既有预算不动。

**决策正文必须明写（决策 #27 D2 的硬性要求）：本次修订不追认 ②**——② 的未达成登记永久成立；新预算是为新架构层命名新账目，不是把失败的测量洗成通过。

## 3. X 的取值依据与建议（业主裁定点）

已签署/已实测证据：

- 现架构（ADR-0033 页槽+哨兵级联，无 P7）：VM p95=**4370.7ms**，max=4430.8ms（run-2b-5，决策 #26 翻正后有效）。
- P7（首窗自适应放宽一页，决策 #27 D5 已登记进 2c 方案表）：分析估计整体 p95 → **~2.5s**（zone-2 级联率实测 10/10 支撑该杠杆，但 **~2.5s 是估计值，未经 VM 批次实测**）。

| 选项 | X | 论证 |
|---|---:|---|
| **A（已裁定）** | **5s** | 以已签署测量 + 余量立账（p95 4370.7 + max 4430.8，余量 ~12–14%）：预算从第一天起就是「已签署证据可承托的账」，不押注未实测的 P7；P7 落地后的改善按回归规则登记为优化，不再动预算文本 |
| B | 4s | 押注 P7 实测达标；若 2c 实测 p95 落在 4–4.4s 区间则预算即失守，须再走一次修订——把未实测估计写进 G0 冻结物的风险 |
| C | 3s | 要求 P7 之外的第二杠杆（P3/P5 组合估计 ~2.0–2.5s 同为未实测估计）；当前无签署证据承托 |

**业主已裁定选项 A（X=5s，决策 #29 D1）**：与 A-04E-2a 的 8s 全量预算同形态（预算值 = 已签署架构能力 + 余量），诚实且不制造未来的失守点。

「交互反馈 ≤1s」的取值依据：层 1 不含 print 固定成本（地板探针与两点分解证其瓶颈在 print-layout），HTML 回流在 30 页语料上为亚秒级工程常态；**但层 1 目前未实现、无测量**——该预算是架构承诺型预算，2c 任务书须自带测量条款（判定器 additive，同 G7 形态），首次 VM 批次若实测超 1s 须如实登记 not_met，不得修订本行。

## 4. 边界与不做

- **不追认 ②**（§2 硬性条款）；不删除、不重解释、不改写任何既有预算行。
- 不改签署基线、签署带 [20553.4, 24300.2]、冻结模板、检查契约、ux-state 冻结契约（P4 已兼容，无需改）。
- 不授权 2c 之外的任何范围（P4 的层 1 UI 细节、P3/P5 采纳与否均归 2c 任务书，业主逐项裁定）。
- 本 ADR 批准前，`performance-budgets.md` 一字不动；批准后由单独 PR 落地 §2 的 additive 编辑（含台账/AGENTS.md 同步），并按 G2-04 门禁过 `pnpm verify`。
- **2c 立项条件（决策 #27 承接）**：本修订批准 = 2c 可启动方案设计与任务书起草；2c 任务书仍须独立 DoR + 双向审查 + 独立审计。

## 5. 后果

- 批准：P4 双层预览获得正式账目（交互反馈 ≤1s / 页槽精确更新 ≤Xs），2c 可按两条新预算立项验收；② 的 not_met 登记永久保留，台账诚实性不损。
- 否决：P4 路径关闭，② 维持永久 not_met，增量架构（ADR-0033/0034）作为已签署能力留存（取消/等价/真增量均已达成），2c 不立项。
- 无论批准与否，run-2b-5/run-p6-3 的全部已登记结论不受影响。
