# ADR-0030：A-03 结构确认口径、状态机位置、A-03/A-05 分界与停止条件可判定定义

- 日期：2026-08-05　状态：已接受（业主裁定 D1–D4 全部采纳任务书建议，[决策 #16](../../决策记录.md)，互引）
- 任务：`A-03`（结构确认与语义编辑工作区）
- 上游：[A-03 任务书](../audits/A-03-implementation-task.md) §0/§3（独立审计角色起草；§0 判定：四条裁定落盘前 A-03 不满足 DoR）

> 本 ADR 只记录业主裁定及其直接推论，不构成实施；实施细则以 A-03 实施
> 任务书 §4 硬边界与 §5 验收标准为准。

## 1. D1：结构确认 = 可纠正复核，产物必须是普通事务

采纳任务书候选口径②：**用户可纠正结构识别错误，纠正产物是一组走 PB-03
事务边界的普通编辑操作**。

- **纠正动作清单**（结构识别纠错范畴，穷尽列举，不得顺手扩大）：
  1. 节点类型纠正——被误判为段落的行提升为标题（及反向降级）；
  2. 列表结构纠正——合并被拆散的列表、拆分被误并的列表；
  3. 节点顺序纠正——移动误排节点（以普通 move 事务表达）。
- **写路径**：纠正动作全部表达为 `@wenshu/editor-transactions` 普通事务；
  **不引入第二条写路径**（ADR-0016 决策 #5 唯一写边界，可 grep 红线：
  UI 侧任何对 `semantic-editor/internal` 的直接引用按 BLOCKER 处理）。
- **可跳过性**：确认步骤**可跳过、不阻断进入编辑工作区**——直接推论自
  已裁定口径：纠正产物是普通事务，跳过确认后在工作区内仍可事后执行
  同类纠正，不存在「确认阶段独占」的能力；与 D2（确认不独立成状态）自洽。
- 排除项：①只读复核（用户看到错改不了，与 ux-spec §2「让用户确认」的
  承诺不符）与③不设独立步骤（丢失 ux-spec 明写的流程节点）均不采纳。

## 2. D2：编辑工作区与结构确认均不进状态机

- 二者作为 **`project-view` 的呈现分支**实现（承 ADR-0029 确立的非状态机
  视图路径）；**不发明第 13 态**，不改 `states-1.0.0.json` 一个字节
  （A-01-followups #4 additive 纪律；1.0.0 刚由 A-01 契约加固棒完成
  12 态 × 5 用户可见字段逐字锚定，此刻扩展代价最高）。
- 若日后确需为新视图引入状态，另开版本化小棒走 host-contract §5 同款
  流程 + 业主批准，**不得在任何实施棒中顺手加**。

## 3. D3：A-03 与 A-05 按「结构 vs 内容」切分

| 面 | A-03（本棒） | A-05 |
|---|---|---|
| 普通表格 | 结构节点：插入、删除、移动、渲染、键盘可达、稳定 ID 与 undo/redo 覆盖；**行列增删属结构操作，归 A-03** | 单元格**内容**编辑、表头语义标记 |
| 图片 | 结构节点：插入、删除、移动、渲染、键盘可达 | **alt 文本**、附件上传、尺寸/数量上限预检 |

- **A-05 开工时须反向引用本条**，逐项对照，既不越界也不留洞。
- 审计对照：两端实施若以同一动作为由双双缺位或双双重合，按本条字面
  归属判定。

## 4. D4：两条停止条件的可判定口径（全部引用既有权威值，不新增阈值）

### (a) 「主线程冻结即阻断」

- **阈值**：[性能预算](../performance-budgets.md)原文——普通键入/选择响应
  **p95 ≤ 100 ms**；其稳定性预算「关键操作不得出现未响应超过 2 秒且没有
  进度/取消反馈」作为**硬阻断线**；
- **语料**：**30,000 字**（预算原文首战上限），落成可复跑 fixture，不得
  临时生成；
- **机器与方法**：G1-14 参考机器 `wenshu-dev-primary`，按
  [reference-machine §3 性能采样协议](../reference-machine.md)执行，
  **重复 10 次取 p95**；
- **判定**：测量落成机器可判的证据文件（原始采样数据落盘），不接受
  「体感不卡」；长任务分片/移出主线程须有实证（预算原文要求）。

### (b) 「结构丢失即阻断」——三条同时成立，任一破即阻断

1. 任意编辑序列后，除**显式删除**的子树外，**既有稳定 ID 集合完整保留**
   （PB-03 提交前校验的 UI 层端到端复验）；
2. 每次提交后文档通过 G1-04 `validateDocument`；
3. undo/redo 往返后与提交后文档 **deep-equal 且不重分配 ID**
   （[ADR-0016](0016-PB-03统一编辑事务边界.md) 后果段原文）。

**三条各配一条决定性测试**：放宽对应守卫的变异必须因正确原因变红，
红在邻近守卫即探针失效、作废重做。

## 5. 后果

  自身排期开工；实施 Codex、独立审计 Claude（任务书起草者声明同款约定）。

  可复跑——审计不退化为品味之争。
