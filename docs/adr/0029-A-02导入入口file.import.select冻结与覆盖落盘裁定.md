# ADR-0029：A-02 导入入口冻结 `file.import.select`（协议 0.3.0）与覆盖/落盘裁定

- 日期：2026-08-03　状态：已接受（业主裁定 D1，[决策 #15](../../决策记录.md)，互引）
- 任务：`A-02`（新建/打开项目与只读导入流程）
- 上游：[任务书](../audits/A-02-implementation-task.md) §3、 [任务书审计](../audits/A-02-implementation-task-claude-audit.md)（含追补一/二）、[host-contract §4/§5](../host-contract.md)、[PB-11-followups #4/#6](../audits/PB-11-followups.md)

## 1. D1：导入入口——业主裁定走选项①，冻结 `file.import.select`

业主不接受"Alpha 不提供任意位置选文件"的产品收窄，任务书审计的选项②裁定按其自失效条款作废。本棒按 [host-contract §5](../host-contract.md) 版本化流程冻结 `file.import.select` payload schema，A-02 按「契约任务 + UI 任务」执行。

### ①-a（红线）：输出绝不能是路径

`file.import.select` 的 output **不含任何系统路径**。选中结果以**不透明 handle** 表达——具体形态为**单文件作用域的 FileGrant**（`grant_id`），真实读取在特权进程内完成（R-1）。`file_name` 仅为显示元数据：独立 leaf `FileDisplayName`（禁 `/`、`\`、`:`、控制字符，禁 `.`/`..`，≤128 字符），**永不参与文件系统寻址**。

依据：host-contract §4"文件与目录位置由 Host 保管；核心只使用受控 `grant_id`、资源 handle 和安全文件名"；值级预检（`security.ts` `isUnsafePathValue`/`isForbiddenPlatformKey`）对任意键名结构性拒绝盘符绝对路径、POSIX/UNC、`file:` URL 与穿越片段。**若 output 携带绝对路径将被现有预检直接拒绝；届时不得放宽预检**——放宽即拆红线，审计 BLOCKER。

### ①-b：协议版本形态——additive 次版本 **0.3.0**（选定）

两候选：(i) 0.2.0 冻结集 7→8（技术上不使既有注册表失效——`validateDeclarationConsistency` 按 `capability_version` 逐项判定，无"恰好 7 项 supported"不变量）；(ii) 新次版本 0.3.0。**选定 (ii)**，理由：

1. PB-10 自身先例（0.1.0→0.2.0）即新文件 + 新协议号，非原地改冻结文件；
2. 仓内"向冻结契约增内容"纪律为 additive 次版本 + 保留冻结版 + 双版本 reader（PA-06B 证据契约、PA-08 检出报告皆然）；
3. `host-payloads-0.2.0.schema.json` 等 0.2.0 文件保持**字节稳定**，既有冻结守卫（7 项精确清单、reused defs byte-identical）原样有效，零回潮面。

形态：新增 `host-0.3.0.schema.json`（信封，`ProtocolVersion` const `0.3.0`，`CapabilityVersion` enum 增 `0.3.0`，schema id pattern 放行 `/0.3.0`，复用叶子 def 与 0.1.0/0.2.0 逐字节一致）+ `host-payloads-0.3.0.schema.json`（仅 `FileImportSelectInput/Output` 与其复用叶子）。reader 三路分发（0.1.0/0.2.0/0.3.0），未来版本照旧 fail-closed。

**决定性测试（业主要求）**：既有 0.2.0 注册表（`file.import.select` 登记为 `/0.1.0` 占位）在新代码下仍须校验通过；0.2.0 请求/终态全链路不变（双版本 in vivo）。

### ①-c：选择器只在 L3 壳

真实文件对话框仅出现在 `apps/electron-shell`（`dialog.showOpenDialog`，`openFile` + `multiSelections`），作为 `selectFiles` 回调注入 file-host（与 `selectDirectory` 同模式）。web/L0/L1/L2 不出现任何选择器；壳不得旁路协议把结果直喂核心——选中结果只经 0.3.0 协议以 handle 回传。浏览器 Host 无法实现导入管线（执行器依赖 L2，web 层结构性不可达），如实将 `file.import.select` 登记为 **unsupported**（fallback 明示桌面壳路径，不回环弹窗）——此即 A-01-followups #3 的评估结论（维持 A-01 已消费的"浏览器 Host 非持久、仅开发联调"文档明示，7 项既有登记不改）。

### R-1（红线，与①-a 并列）：契约层不新增读原语

handle 之后的真实读取沿用 PB-11 先例：特权进程内 L2 `node:fs`、grant 边界 fail-closed。**不得**借本次冻结顺手在契约层新增 `file.read` 之类读能力——出现即 BLOCKER。

### R-2：handle 生命周期——会话级、一次性、进程死亡即失效

- **会话级**：FileGrant 存于内存 GrantTable，进程退出即灭（重启后必然失效，无持久化路径）。
- **一次性（consume-on-read）**：读取即原子取出并注销（checkout 语义）；同一 handle 二次使用 → fail-closed `NOT_FOUND`。导入完成、取消或放弃后不留存授权。
- 理由：可重放且不过期的 handle 等于把"任意位置的那个文件"变成永久授权——那正是走①换来的便利所必须拒绝的代价（业主原话）。
- **反例（决定性测试）**：吊销/消费后再用 → 稳定 `NOT_FOUND`；变异守卫（删消费检查）→ 测试变红。

### R-3：handle 作用域钉死为单文件

FileGrant 钉定**一个**绝对路径（选择时刻 stat + sha256 + size 快照）；不隐式授权所在目录。多选时**每个文件一张独立 FileGrant**。Markdown 引用的资源文件若未被用户一并选中 → 该资源进入部分失败（见 §4），绝不扩大授权去"顺便"读同目录文件。

- **反例（决定性测试）**：拿源文件 handle 读同目录另一文件 → 必须被拒（handle 只解析到钉定路径，无目录推导）；变异守卫（作用域放宽为目录前缀匹配）→ 测试变红。
- 选择后文件被改写：读取时重算 sha256 与快照不符 → `INTEGRITY_FAILURE` fail-closed（同时为"原件哈希不变"证据提供锚点）。

## 2. D2：覆盖/合并策略——拒绝 + 引导另选/另建，merge 契约级排除

导入/新建的目标目录**必须事先不存在**（沿用 PB-11 语义）。已存在时：**拒绝并呈现原因，引导用户另选名称或另建**；**禁止**任何"合并进已有项目目录"路径——与停止条件"任何原地修改即阻断"直接冲突，未经业主另行批准并更新路线图该行不得出现。冲突呈现守 document-model §7.2 同款口径：不静默换名、不自动加后缀。

## 3. D3：原件落盘布局与保护登记

采用布局 (b)（PB-11 已审模式）：

```text
<targetRoot>/                  必须事先不存在（D2）
  document.json                v0 文档（JSON.stringify，与 PB-12 落盘先例一致；空项目可不存在该文件）
  assets/<sha256前16>.<ext>    决策 #7 内容寻址资源（子目录，Host 写结构性不可达）
  materials/<sha256前16>.md    原件副本（子目录，Host 写结构性不可达）
```

- 原件本体**只读不動**；落盘的是副本。
- 每个落盘原件副本（materials 的 .md + assets 的资源）都在项目 grant 上 `protectImportedFile(平文件名)` 登记——平文件名覆盖 Host 唯一可寻址的同名列（grant 根直下），与 PB-11 #4 的等效性论证逐字一致；**登记名与真实落点一致**（内容寻址名即真实落点名）。
- **不引入可寻址子路径的写能力**——Host 写仍只能寻址 grant 根直下平文件名，PB-11 #4 的重估触发条件不成立。PB-11 #4/#6 随本棒关闭。
- 空项目约定：新建空项目只建目录（document.json 尚不存在——v0.1.0 要求 blocks ≥1，不伪造空块）；打开无 document.json 的目录 = 合法空项目（`empty-project` 态）；打开含损坏 document.json 的目录 = 显式失败，不静默重建。

## 4. 导入执行与四态语义

- **执行器**放 `packages/markdown-import`（L2，新增对 `@wenshu/project-storage` 的 workspace 依赖，L2→L2 有 knowledge-package 先例）：事务骨架照 PB-11——目标存在即拒 → 兄弟临时目录（`IMPORT_TEMP_MARKER` 单源，孤儿由 `recoverGrantDirectory` 既有双前缀回收）→ 读取/解析/写入 → rename 原子转正 → 失败/取消 rm 临时目录。**任何写操作不触碰源文件**；守卫变异（写路径指向原件）→ 对应测试因正确原因变红。
- **解析入口 additive**：新增"从文本 + 资源解析回调"入口（现有路径入口不动）；**逐资源失败收集**——单个资源不可读/未选中/歧义 → 该 figure 降级为失败项（不进文档），导入继续，产出 `failedAssets[{file_name, reason_code, retryable:true}]`；全部资源失败而正文成功仍是 partial。整体失败（正文解析失败/目标存在/权限拒绝）才整体失败。
- **编排通道**：壳新增白名单 IPC（`wenshu.project.new/open/import` + 进度事件 + 取消），只携带 `grant_id`、平目录名与显示元数据，**无路径**；壳侧仅做薄适配（对话框、GrantTable 注入、错误码映射），核心逻辑全在 L2。依据：PB-11/PB-12 先例（导入在 main 进程经 L2 直接执行）；协议边界管平台能力，编排是应用逻辑。
- **四态消费**：`empty-project`/`importing`/`import-partial`/`permission-denied` 的 `requiredPresentation`/`forbiddenSemantics`/`a11y` 是契约义务。共享流程控制器放 `@wenshu/ux-state` 的 **additive 模块**（`stateVersion 1.0.0` 数据零改动，A-01-followups #4 纪律）：以 `canTransition` 守转移合法性，统一 apps/web 与 E2E 场景两消费者的呈现义务对账。取消 = `cancelled` 终态不伪装成 failure；部分失败逐项呈现（不整体吞掉结果）；权限拒绝 = `HOST_PERMISSION_DENIED` + 显式降级、不回显系统路径、不循环弹窗。
- **A-01-followups #1（Ajv 145 kB）**：ux-state 新增**纯数据子路径** `./data`（不经 Ajv；additive，冻结 JSON 与现有入口不动），apps/web 改从子路径消费；以"子路径数据 === 经 Ajv 校验的 UX_STATES"平价守卫测试防漂移；瘦身前后 bundle 体积记入实施记录，不默认接受原体积。
- **A-01-followups #2（types:["node"]）**：本棒扩大 apps/web 代码面，**处置**：移除 tsconfig 全局 `types:["node"]`，改为仅在 `vite.config.ts` 与 `test/**` 以逐文件 `/// <reference types="node" />` 引入——`typecheck` 脚本逐字串不变、typecheck-coverage 全覆盖不变（同一 tsconfig.json），`src/` 类型层面不再见 node 全局。门禁双锁（逐字脚本 + 全覆盖）均不触发。

## 5. 明确不做

- 不新增契约层读原语（R-1）；不放宽值级预检（①-a）；不引入可寻址子路径写能力（D3）；不提供合并语义（D2）；docx（A-02D）；语义编辑工作区（A-03）；模板/预览/分页（A-04）；附件与表格编辑（A-05）；项目列表与搜索（A-11）；AI 任何面。
- 符号链接/realpath 穿透评估归 A-15（PB-11 #7 同类），FileGrant 钉定路径沿用字符串语义并在实施记录登记。

- A-02 承接项处置：关闭 PB-11 #4/#6、A-01 #1/#3；A-01 #2 按 §4 处置后如实说明；A-01 #4 遵守（1.0.0 零改动）；PB-10 #1 行为要求由 §3 的 protectImportedFile 登记真实履行（条目已由 PB-12 关闭，不再关一次）。
