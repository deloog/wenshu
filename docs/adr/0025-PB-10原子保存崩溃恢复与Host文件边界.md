# ADR-0025：PB-10 原子保存、崩溃恢复与 Host 文件边界

- 日期：2026-07-31
- 状态：已实现，待 Claude 独立审计
- 决定：将 Host 协议从 `0.1.0` additive 升级到 `0.2.0`，冻结 7 项文件/项目能力
  的输入/输出 payload Schema；在 `@wenshu/project-storage` 内实现值级路径预检、
  授权目录（grant）、原子写（temp→fsync→rename→dir-fsync）与崩溃残留恢复；
  在 `apps/web` 内提供浏览器受控 Host 模拟，不冒充平台实现。

## 决策依据

### 1. 协议升级必须 additive

`0.1.0` 由 G1-06 冻结，仅规定能力注册表、请求生命周期与错误/取消/进度语义，
未定义具体能力的输入/输出 Schema。PB-10 要实现真实 Host 调用，必须让核心与 Host
之间的消息有可校验的结构真源。因此新增 `0.2.0`：

- `protocol_version` 为 `0.2.0` 的注册表必须将 7 项能力登记为 `supported`，其余 11
  项保持 `unsupported` 并给出显式 fallback；
- 每项 `supported/degraded` 能力必须指向冻结的 payload schema ID
  `wenshu.host.{input,output}.<cap>/0.2.0`；
- `validateHostContract` 对 `0.2.0` 做注册表一致性 + payload schema 存在性校验；
  `validateHostPayload` 供 Host 实现者在运行时校验单条消息；
- `0.1.0` 注册表与校验路径完整保留，既有 G1 契约测试不漂移。

### 2. 文件边界的三道防线

核心不能直接接触绝对路径；文件/项目保存通过授权目录（grant）进行：

1. **契约层**：`0.2.0` payload schema 要求 `grant_id` + `file_name`，禁止任何
   `path`、`filesystem` 等字段；`host-contract` 的值拒绝逻辑继续拦截 NUL/控制字符、
   盘符绝对路径、POSIX/UNC 路径、`file:` URL、`..` 穿越片段与百分号编码攻击；
2. **注册表层**：`createGrantStore` 将不透明的 `grant_id` 映射到宿主进程内的目录；
   核心永远不会拿到目录字符串；
3. **值级路径层**：`resolveGrantFile` 只接受 ASCII 安全文件名（`A–Z a–z 0–9 -_.`），
   拒绝空串、路径分隔符、`..`、控制字符、隐藏文件、Windows 保留设备名与尾点；
   解析后的目录名比较做 fail-closed 检查是否逃逸授权根目录；导入原件登记为只读，
   `file.export.write` 即便 `overwrite:true` 也无法覆盖。

### 3. 原子写与崩溃恢复

`atomicWriteFile` 采用 POSIX 推荐的写入序列：

```text
temp file → fsync data → rename → fsync parent directory
```

- Windows 对目录 `fsync` 返回 `EPERM`，因此显式跳过并记录为
  `dir-fsync-unsupported`，不伪装已执行；
- 崩溃残留文件以 `.wenshu-tmp-` 前缀命名，`recoverGrantDirectory` 只删除这些残留，
  绝不猜测或补全其他文件；
- 测试通过 `SIGKILL` 强杀子进程在 4 个相位（temp-created、data-written-partial、
  data-fsynced、renamed）中断写入，验证“上次完整文件始终不变”。

### 4. 浏览器 Host 是确定性模拟

`apps/web/src/host.ts` 在内存中实现 7 项 `0.2.0` 能力，用于开发与 UI 联调：

- 使用 `globalThis.crypto.subtle` 做 SHA-256，`crypto.getRandomValues` 生成 grant ID，
  `atob` 做 base64 解码，避免在 web 层引入 `node:crypto`/`Buffer`；
- 支持权限拒绝、用户取消、超时、降级路径与只读 fallback；
- 不访问真实文件系统，也不冒充 Electron/ArkWeb 平台实现。

## 未选择与后续

- 不覆盖导入原件：`file.export.write` 提供 `overwrite` 标志，默认 fail-closed；
  保存/备份只操作授权目录内的文件。
- 不实现打印/分页路径：PoC-A 排版路径已按决策 #11A DEGRADE，`print.pdf.export` 在
  `0.2.0` 注册表中保持 `unsupported`。
- ArkWeb 文件桥仍标记为 `needs_device_to_verify`；本任务未在 ArkWeb 真机或模拟器上
  验证，浏览器结果不冒充 ArkWeb 结果。
- Electron-shell 仅添加 `@wenshu/project-storage` 依赖并通过 typecheck；preload 与
  renderer 集成不在 PB-10 范围内，待 PA-14E/A-02 平台验证时续接。
