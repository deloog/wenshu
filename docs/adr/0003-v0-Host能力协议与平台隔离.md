# ADR-0003：v0 Host 能力协议与平台隔离

- 日期：2026-07-20
- 状态：已接受（G1-06）
- 关联：宪法 11/15、冻结纲领 Host 能力注册表、R-HOST/R-UX/R-SEC、ADR-0001

## 背景

文枢的 Web 核心需要跨浏览器、Electron 和 ArkWeb 复用，同时文件、打印、窗口、分享、外链和安全存储具有不同权限与生命周期。如果核心直接判断平台或调用平台 API，会复制业务逻辑、泄漏高权限类型，并让拒绝、取消和降级行为不可测试。

## 决策

1. 冻结平台中立 Host 协议 `0.1.0`，能力名、注册表和请求生命周期以 JSON Schema 为真源并生成 TypeScript。
2. v0 固定 18 项能力白名单；每个 Host 必须显式声明全部能力的 supported、degraded 或 unsupported 状态。
3. 每项能力声明参数/返回 Schema ID、调用预算、权限、生命周期、取消、进度、错误与降级；具体实现没有对应 Schema 和验证器时不得宣称生产支持。
4. 请求使用不透明 ID；取消、进度和唯一终态分离。权限拒绝与超时是稳定错误，取消具有独立终态。
5. 核心不交换任意系统路径或平台对象，只交换受控 grant/handle 和 JSON 数据。Electron IPC、Node、ArkTS 类型不得进入公共协议。
6. 浏览器 fake 只用于核心单元/契约测试；Electron、ArkWeb、文件、打印和权限结论必须由各自真实实现验证。

## 结果

- Web 核心可以依赖一种协议并显式处理平台差异。
- unsupported/degraded 成为正常、可测试状态，而不是运行时意外。
- 高权限平台错误被收窄为稳定错误码，避免路径、密钥和系统异常泄漏。
- 后续能力 payload Schema 与平台实现必须在此边界内扩展，不能绕过注册表。

## 撤销或升级条件

- 某项能力无法在不泄漏平台类型的情况下表达；
- 真实 Electron/ArkWeb 探针证明生命周期模型不足；
- 需要新增高权限能力或改变参数、权限、取消、错误语义。

发生上述情况必须升级协议/能力版本，提供兼容与回滚说明并重跑全部消费者契约；不得原地改变 `0.1.0`。
