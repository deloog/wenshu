# G1-04 v0 文档对象契约

> 状态：已完成（Claude 独立复审 `CONDITIONAL PASS`）　Schema 版本：`0.1.0`　日期：2026-07-20

## 1. 目的与边界

本契约只定义文枢首战所需的文档真源结构，不实现编辑器、排版、持久化、平台 API 或模板执行。v0 可以表达标题层级、段落、列表、引用、普通表格、图片/图表引用和显式分页标记；复杂表格、富文本行内标记、公式、脚本和任意外部资源不在本版本范围内。

权威真源是 [`packages/document-model/schema/document.schema.json`](../packages/document-model/schema/document.schema.json)。TypeScript 声明由 schema 生成，不得手工编辑；运行时先做 JSON Schema 校验，再做跨对象引用与唯一性校验。

## 2. 顶层对象与内容模块

`WenshuDocument` 固定包含：

- `schemaVersion`：当前只接受精确值 `0.1.0`；
- `documentId`：文档稳定标识；
- `revision`：非负修订号；
- `title`、`language`：标题与受控语言标签；v0 只接受 `language[-Script][-REGION]` 子集，不宣称覆盖完整 BCP 47；
- `blocks`：至少一个内容块；
- `assets`：文档引用的受控资源清单。

内容块使用可判别联合：`section`、`paragraph`、`list`、`quote`、`table`、`figure`、`pageBreak`。对象默认拒绝未知字段。表格必须让每行恰好覆盖全部已声明列；figure 必须指向清单中的资源。资源路径采用正向 ASCII 相对路径白名单，拒绝盘符、绝对路径、URL、`.`/`..` 段和反斜杠；同时限定图片媒体类型和 64 位小写十六进制 SHA-256。

## 3. 稳定 ID 规则

所有 ID 都是不透明的“前缀 + 128 位小写十六进制值”，不得编码数组位置、标题、文件路径或业务含义：

| 对象 | 前缀 |
|---|---|
| 文档 | `doc_` |
| 内容块 | `node_` |
| 列表项 | `item_` |
| 表格列/行/单元格 | `col_` / `row_` / `cell_` |
| 资源 | `asset_` |

- 新对象创建或首次导入时分配一次 ID。
- 改写、移动、重新排版和导出不得改变既有 ID。
- 复制形成的新对象必须获得新 ID；导入冲突必须显式解决，不能静默覆盖。
- 当前文档内所有上述 ID 共享唯一性约束。

## 4. 版本与兼容规则

- 当前 reader 只接受 `0.1.0`，未来版本必须明确拒绝，禁止“尽力读取”后静默丢字段。
- 任何 schema 变化都先修改 JSON Schema、fixture 和兼容说明，再重新生成类型并通过漂移检查。
- `0.x` 阶段的新增或行为变化发布为新的次版本，并提供显式迁移/适配器；不得在原版本下改变语义。
- 删除、重命名、改变字段含义或使旧数据不可读属于破坏性变化，需要新主版本、迁移与架构决策审查。
- 生成物可删除重建，永远不是唯一真源；旧 schema 与迁移链在产生真实数据后不得改写。

## 5. 安全与诊断

公共验证入口接收 `unknown`，先以最多 64 层、100,000 个对象/数组节点的预算检查输入，再执行 Schema 与跨对象校验；超限会返回稳定问题而不是抛出运行时栈溢出。输入还会拒绝函数、访问器、循环和非普通对象，且不会读取继承访问器。成功后返回深复制、深冻结的类型化对象，避免调用方继续篡改输入。失败只返回稳定 issue code 与 JSON 路径，不回显正文、标题或资源内容。第三方库类型通过本地窄接口收口，项目手写 TypeScript 不使用 `any`。

当前稳定问题码为：`DOCUMENT_SCHEMA`、`DOCUMENT_BUDGET_EXCEEDED`、`DOCUMENT_DUPLICATE_ID`、`DOCUMENT_REFERENCE_MISSING`、`DOCUMENT_TABLE_COLUMN_MISMATCH`。

## 6. 生成、验证与证据

- `pnpm --filter @wenshu/document-model generate`：从 schema 生成 TypeScript 声明。
- `pnpm --filter @wenshu/document-model generate:check`：检查声明是否与 schema 漂移。
- `pnpm contracts:check`：运行文档与模板漂移检查及全部契约 fixture。
- `pnpm verify`：配置契约、文档契约、严格类型检查和生产构建的统一入口。

修复后自检证据：2 个合法 fixture 与 7 个非法 fixture 全部符合预期，共 15/15 测试通过；Windows 绝对路径、远程 URL 与深层输入均有负向测试；测试目录已纳入该包严格 TypeScript 检查。故意修改生成文件后漂移检查按预期失败，重新生成后恢复通过；最终结论仍等待独立复审。使用 Ajv `8.20.0` 做 JSON Schema 2020-12 运行时校验，使用 json-schema-to-typescript `15.0.4` 生成声明，两者均为 MIT 许可；精确版本与完整性由 lockfile 固定，完整供应链结论仍由 `G1-15` 签署。

## 7. 资源文件名策略（PA-00 裁定，2026-07-23）

**裁定：导入时安全规范化重命名（选项 A）。** v0.1.0 的正向 ASCII 相对路径白名单**保持不变、不放宽、不升级 Schema**；任何来自用户/上游的原始文件名不得直接进入文档对象与文件系统。PoC-A 目标是排版验证，冻结 Schema 在 PoC-A 期间不因文件名问题被迫改动（NF-03 关闭）。

### 7.1 固定决策矩阵

| 输入形态 | 示例 | 裁定 |
|---|---|---|
| 中文文件名 | `资产/图表1.png` | 导入期重命名为规范名，原名留痕（§7.2） |
| 中文 + 空格 | `assets/图 1.png` | 同上 |
| 大写扩展名 | `photo.PNG` | 扩展名小写化；mediaType 按内容核验，不信任扩展名 |
| 目录含点 | `v1.2/chart.svg` | 目录扁平化重命名，原名留痕 |
| webp | `chart.webp` | v0 不支持：明确拒绝并提示转换为 png/jpeg（模板媒体类型仅 png/jpg/jpeg/svg） |
| gif / bmp | `anim.gif`、`scan.bmp` | v0 不支持：明确拒绝并提示转换为 png/jpeg（同上白名单，无例外） |
| Windows 保留字符 `< > " \| ? *` | `a<b.png` | 规范化剔除后重命名 |
| Windows 保留设备名 | `con.png`、`aux.svg` | 规范化重命名规避 |
| 尾随点/空格 | `a .png`、`a.png␣` | 规范化剔除 |
| Unicode 规范化差异（NFC/NFD） | 变体文件名 | 原名仅作留痕字符串，永不落盘，故无规范化碰撞面 |
| 大小写碰撞（NTFS） | `A.png` 与 `a.png` | 规范名按内容寻址生成（§7.2），无碰撞面 |
| 无扩展名源文件 | `assets/diagram`（内容为 PNG） | 扩展名由内容 sniff（魔数）推导：可识别为 png/jpg/jpeg/svg → 按推导扩展名重命名；不可识别或不在白名单 → 拒绝 |
| 远程 URL 引用 | `![](https://example.com/x.png)` | **明确拒绝**（本地优先、离线确定性、来源可锚定）：提示用户先下载到本地再导入；v0 不做任何网络抓取 |
| 源路径穿越/绝对 | `../../secret.png`、`D:\\else\\x.png` | 导入器只读声明的导入根之内：拒绝绝对路径与任何解析后越出导入根的路径，fail-closed 不读取 |

### 7.2 规范化重命名规则（导入器实现约束，PA-01/A-02D 消费）

- 目标名确定性地由**内容寻址**生成：`assets/<sha256 前 16 位>.<小写扩展名>`；同内容重导入幂等复用。
- **冲突处理（fail-closed）**：目标名已存在时比对完整 SHA-256——内容相同则复用，**内容不同即拒绝并报冲突，不得静默覆盖或自动换名**（截断哈希理论碰撞面以显式拒绝兜底，不依赖“天然无碰撞”表述）。
- 扩展名规则：源文件带白名单扩展名 → 小写化；**无扩展名 → 由内容 sniff（魔数）推导**；sniff 结果与声明扩展名不符、或无法识别、或不在白名单（`png/jpg/jpeg/svg`）→ 拒绝。媒体类型永远以内容为准，不信任扩展名。
- 读取边界：导入器仅接受导入根内的相对路径；绝对路径与任何解析后越出导入根的路径在**读取前**拒绝。
- 远程引用：Markdown/HTML 中的 `http(s)://` 资源引用在解析期拒绝并给出“先下载再导入”的稳定提示；v0 不引入任何网络获取能力。
- **原名留痕**：导入报告记录 `原始路径 → 规范路径` 映射，并写入语义审计事件（project-contract 既有机制）；原名永不写入文档对象、永不落盘。
- 文档对象内的 `asset.path` 只可能出现规范化后的白名单路径，下游（渲染/PDF/打包）无需新增任何兼容分支。

### 7.3 关联裁定

- fixture 可移植字符规则已按 FX-06 补齐：`isCanonicalFixturePath` 逐段拒绝 `< > " | ? *`（见 fixture-integrity.md §路径），与文档对象白名单互为独立两层，不互相借用。

## 8. 导入期 ID 派生约束（PA-A5/A6 裁定，2026-07-24，决策 #8/#9 均已批准）

> 本节是 `@wenshu/markdown-import` 的实现约束，对应 [决策记录](../决策记录.md) #8/#9；不修改本文件 §2/§3 的冻结契约，Schema 零变更。

### 8.1 节点 ID：复合摘要种子（PA-A5）

- 禁止十进制位宽算术打包（如 `ordinal*10000+row*100+cell`）。层级位置以分隔符分层种子串喂入 SHA-256 输入（`种子:kind:内容摘要`）：节点 = `ordinal`；列表项/表格列 = `ordinal:index`；表格行 = `ordinal:rowIndex`；单元格 = `ordinal:rowIndex:cellIndex`。构造单射、无输入规模上限。
- **承重不变量：`kind` 必须始终取自非数字词汇表**（当前 11 个 kind 全非数字）——kind 非数字且紧邻内容摘要，种子前缀才与内容无歧义分界；新增纯数字 kind 即破单射，演进时必须设防。
- ID 外在形式不变：`前缀_` + 32 个十六进制字符（128 比特）（§3）。
- 派生必须保持 PA-01 已审三性质：同输入幂等；同文档内全部 ID 唯一（重复仍由 `DOCUMENT_DUPLICATE_ID` fail-closed）；输入变更 → 仅受影响节点 ID 变更。
- schema 门禁错误信息必须携带 `validateDocument` 的稳定 issues（`code` + JSON `path`），不回显正文、标题或资源内容（§5）。

### 8.2 `documentId`：跨修订稳定标识（PA-A6）

- 语义：`documentId` 是跨修订稳定标识（与 `revision` 配合），不是内容身份；内容去重属项目层职责。
- 派生：`doc_` + SHA-256（`"wenshu/import/v0"` + 源文件相对导入根的 POSIX 相对路径 + `title`）前 32 个十六进制字符（128 比特）。**v0 导入根为调用方显式声明的公共目录（必填，无默认值）**，源文件必须位于导入根内，否则 fail-closed；禁止以「每个源文件各自目录」为根（相对路径退化为 basename 会在跨目录同名文件间再造 PA-A6 碰撞）。资产引用仍以源文件目录为相对基准解析，不得越出声明的导入根（§7.2 不变）。
- 性质：同路径同标题重导入（含内容修订）→ 同 ID；不同路径同名文档 → 不同 ID；标题改写 → 新身份（v0 显式语义）。
- 残余碰撞面（同路径同标题不同内容）按同一文档新修订处理；导入冲突显式解决，不静默覆盖（§3）。
