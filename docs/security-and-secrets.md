# 文枢安全与密钥策略（G0）

## 密钥规则

- 真实 API key、签名证书、密码和 token 永不进入仓库、项目包、模板、日志、截图或测试 fixture。
- G1 仅提交 `.env.example` 的变量名和无效示例；真实值使用 OS 安全存储、CI secrets 或部署平台密钥库。
- BYOK 凭证按 provider 隔离，界面只显示掩码；复制、导出、诊断和崩溃报告默认排除。
- 密钥读取只发生在最小适配层；Web 核心和文档对象不得持有明文密钥。
- 密钥支持撤销、替换和清除；认证失败不得把 key 打进错误信息。

## 开发与测试

- 本地、测试、staging、production 凭证完全分离。
- 测试默认使用无费用 fake/沙箱凭证；真实模型冒烟须显式标记、限额并取得费用批准。
- 提交前与 CI 双重扫描密钥；发现泄露按“立即撤销 → 清理传播面 → 复盘”处理，不能只删 Git 当前文件。
- 生产数据默认不进入开发/测试；确需复现时使用最小脱敏样本并获得批准。

## G1 落地要求

- `.gitignore` 在首提交前覆盖 `.env*`（保留 `.env.example`）、证书、密钥库、本地项目和编辑器历史。
- 配置 schema 在启动时校验，缺失或格式错误应快速失败；不得静默使用生产默认值。
- 日志库实施字段级脱敏；错误追踪上传前过滤正文、路径、凭证和个人信息。
- 建立 `scripts/scan-secrets` 或等价工具，并纳入本地提交钩子和 CI。
