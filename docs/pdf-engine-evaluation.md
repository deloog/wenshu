# PoC-A 排版引擎评估记录：Chromium vs Typst（WASM）

> 日期：2026-07-21　来源：决策 #5（竞品调研报告 §G 建议将 Typst 列入评估对照）　性质：评估记录，不改变路线图已锁定的 Chromium 路径；PA-05 开工前据此复核一次。

## 候选

| 维度 | Chromium 打印（路线图已锁定，PA-05） | Typst（WASM，对照候选） |
|---|---|---|
| 管线一致性 | 与 PA-03 语义 HTML 渲染、PA-04 模板 CSS 解释**同一条管线**，浏览器即渲染器，无第二投资 | 需另建"文档模型→Typst DSL"映射，与 PA-03/04 形成第二条并行渲染管线 |
| 字体 | PA-03 已有真实浏览器字体加载检查；G1-13 冻结 OTF 直接 `@font-face` 使用 | 字体需经 Typst 字体索引另行登记，WASM 环境字体供给链路需重建与重测 |
| 中文成熟度 | 浏览器 CJK 排版（断行、标点挤压）为生产级 | Typst CJK 断行/标点规则仍在演进，中文长文生产案例少 |
| 页眉页脚/页码/目录 | 依赖浏览器打印能力，触顶时按路线图记录受控补偿（PA-11） | 原生页码/页眉页脚/目录能力强且确定 |
| 确定性/性能 | 打印结果受浏览器版本影响，故 G1-02 锁定版本、G1-14W 固定环境 | 增量编译、输出确定性更强 |
| 生态与许可 | 已锁定工具链（ADR-0002），零新增依赖 | Rust/WASM 工具链新增，供应链与体积成本增加；Apache-2.0 许可无碍 |

## 结论

1. **维持 Chromium**。决定性理由是管线一致性：PA-03/04 已把"文档模型→语义 HTML→CSS 布局"作为主投资，引入 Typst 等于推翻该投资并双管线维护；CJK 成熟度与字体链路是次级风险。
2. **Typst 保留为降级对照**：若 PA-11 证明浏览器页眉页脚/目录页码能力触顶且无法受控补偿，或 PA-13 性能预算无法达成，按本记录重新评估 Typst（或 Paged.js/WeasyPrint）作为替换渲染后端，评估须写 ADR 并重审消费者。
3. 本记录满足竞品报告"Typst 列入评估对照"的建议；Typst 证明"确定性排版+模板系统"工程可行，是对我们路线的间接背书而非反证。

## PA-05 开工前复核（2026-07-24，实施者书面复核）

按本记录要求复核一次，**结论维持 Chromium**：①管线一致性理由较评估时更强——PA-03（语义 HTML）、PA-04（白名单 CSS）已审 PASS 合入，"文档模型→语义 HTML→CSS 布局→浏览器打印"主投资已成链，引入第二渲染后端的推翻成本只增不减；②字体链路已在真实浏览器经三字重门禁实证（PA-03），Typst 路线需重建的正是这条已验证链路；③页眉页脚/目录触顶风险按既定出口处理（PA-11 受控补偿，不足再按本记录重评 Typst 并写 ADR）；④评估期 Win11 参考环境（G1-14W）已签署可用，Chromium 版本锁定在本任务内补齐登记。复核范围限于确认，不改变任何已冻结结论。

## DEGRADE 后实测重审（2026-07-29）

**结论：不批准换引擎；维持 DEGRADE 与 PB/Alpha 排版依赖冻结。** 8 秒预算和 PDF 合格标准均未改动。本文的数值仅包含性能/对账定位，不回显文档正文。

| 维度 | Chromium（正式参考 VM） | Typst 0.15.1（最小候选探针） | 判定 |
|---|---:|---:|---|
| 30 页分页 p95 | 24.300s（PA-13，Win11/Edge 150，预热+10 次） | 0.200s（Win10 本地、预热+10 次） | Typst 数值**不是**预算通过证据：环境非参考 VM，且产物未过合格性检查。 |
| 根因 | `renderMs` 20.553–24.300s；导入约 0.12s、后处理约 0.61s | 不适用 | 超预算集中于真实浏览器渲染/分页。 |
| 两遍 TOC 分解 | `not_measured` | 不适用 | 评估副本已加首遍/稳定化计时；复用 PA-11A bootstrap 的独立差分 VM 未进入 User Startup，未取得有效批次，故不将其伪称分解结果。 |
| PDF 合格标准 | 已由 PA-05/11A/12 签署 | 10/10 被既有检查器拒绝：Typst XMP 过滤不受当前 `inspectPdf` 契约支持 | 快而错/不可验者不合格。 |
| 文档模型覆盖 | 完整 HTML/CSS、TOC、SVG、表格、压印、检查链 | 文本映射仅；表格/SVG/TOC/压印语义未实现 | 不具备签署内容对账资格。 |
| 字体/供应链 | 冻结 Source Han 字体、既有锁定链 | 官方 Typst v0.15.1 Windows x64，SHA-256 `19ce…6736`，Apache-2.0；探针识别 Source Han Sans | 候选工具许可可接受；若进入产品仍须经批准、锁定、SBOM 与字体链复审。 |
| 确定性 | PA-11A normalized 双跑成立 | 未测：产物在合格性检查前失败 | 不宣布通过。 |

### 诚实边界与建议

1. PA-13 的 24.300s 是唯一正式性能结论，仍为 `not_met`（相对 8 秒为 3.04×）。现有数据不足以将两遍 TOC 与单次 CJK 打印各自量化；不得据此声称“删一遍即可达标”。
2. 为获得阶段分解创建了独立、可丢弃的 Win11 差分 VM；它未复现 PA-11A 已签署盘的 User Startup 自动登录，未生成 `DONE` 或原始运行证据。该失败已隔离，原 VM、签署基线、模板、检查规则均未写入。它不改变 PA-13 正式采样。
3. Typst 的最小文本探针显示编译速度值得后续研究，但同时证明它尚不能接入当前 PDF 检查契约，更没有完成签署内容、CJK 断行/标点质量、几何、validator、双跑确定性或参考 VM 性能验证。不得把 demo 速度外推为生产成熟度。
4. 建议业主**不批准引擎替换**。若要解除 DEGRADE，只能另立任务，先在不改冻结标准的前提下完成：Chromium 阶段级正式采样与≤8s 的正确性对账，或完整 Typst 适配器与检查契约兼容性、签署内容/CJK/确定性/供应链和参考 VM 十次采样的全部复验；任一路径均须新 ADR 与业主批准。
