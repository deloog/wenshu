# PoC-A 冻结 fixture 完整性与隔离复制基线

> 状态：G1-10 已完成（Claude 最终复核 `PASS`）。实施日期：2026-07-20；签署日期：2026-07-21。新增可移植字符集 MINOR `FX-06` 已登记到 PA-00，不影响当前 7 个冻结原件。

## 1. 边界与真源

`docs/poc-a/fixtures/` 中原有的 7 个 PoC-A 文件是冻结原件。G1-10 没有改写这些文件，只新增同目录 `manifest.json`，逐项登记规范相对路径、原始字节数和 SHA-256。manifest 本身的完整字节哈希再由校验器中的固定锚点锁定，防止同时改写原件和清单后仍被误判为通过。

校验器动态枚举冻结目录，要求实际文件集合与清单精确相等；缺失、多余、重名、Windows 大小写碰撞、非规范路径、符号链接/目录联接、非常规文件类型、字节数或哈希不一致均快速失败。错误只包含稳定分类和相对路径，不读取链接目标，也不回显文件正文。

清单路径必须同时适用于 Windows 与 POSIX：禁止绝对/盘符相对路径、反斜杠、NTFS 数据流冒号、Windows 保留设备名、尾随点或空格、控制字符和穿越片段；受控 Unicode、普通空格及大写扩展名允许保留。

冻结原件的正式变更不得通过“顺手更新哈希”完成。必须停止消费者、说明变更原因，按 fixture 版本和相关契约重新审计；单独修改 manifest 或固定锚点不能构成批准。

## 2. 运行时只写隔离副本

`copyVerifiedFixtureSet` 只接受 `@wenshu/test-support` 在当前进程真实签发且磁盘 claim 有效的 `PreparedTestIsolation`。调用顺序为：

1. 对冻结目录、manifest 锚点、文件集合和全部字节做完整校验；
2. 在该 worker 独占的 `files/poc-a-fixtures/` 下排他创建副本；
3. 每个文件写入前重新核验源字节，写入后重新核验副本；
4. 全部复制完成后再次核验冻结目录；
5. 排他写入 `files/fixture-copy-manifest.json`。

复制和证据文件均使用只新建语义；已存在目标不会被覆盖。API 不接受任意输出目录，不写 `docs/poc-a/fixtures/`，也不把绝对源路径或隔离目录写入证据 manifest。若运行失败，已产生的隔离副本可保留诊断，但不能被当作完整证据。

文件系统无法阻止另一个有仓库写权限的进程在函数返回之后改写原件；因此每次消费前仍必须运行校验，CI/评审权限负责阻止未经批准的冻结文件变更。

## 3. 证据 manifest

成功复制的证据只记录：

- 证据 schema、fixture set 和 fixture 版本；
- 固定 manifest 的 SHA-256；
- 隔离测试项目 ID 与相对复制根；
- 7 个文件的相对路径、字节数和 SHA-256。

证据不记录机器绝对路径、真实用户数据、正文、密钥或外部账号。它证明本次隔离副本来自已冻结字节，不替代后续 PDF、渲染或用户验收证据。

## 4. 权威命令与测试真实性

- `pnpm fixtures:check`：校验已提交冻结目录，运行 manifest 契约测试和真实文件系统复制/篡改集成测试。
- `pnpm test:integration`：全仓登记的真实集成层现已包含 G1-10 文件系统复制用例；不使用文件系统 mock。
- `pnpm verify`：已串联 `fixtures:check`；本地 CI 的 `contracts` 作业也执行同一命令。

现有反例覆盖 7 个原件分别改变一个字节、manifest 改写、文件缺失/多余、目录联接、伪造隔离句柄、重复复制和绝对路径证据泄漏。G1-10 不涉及数据库；未来涉及数据库的集成测试仍必须运行生产同类真库和真实迁移。
