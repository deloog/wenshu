# 文枢审批矩阵

> 项目业主为非技术背景。AI 应在已批准的产品、预算、安全、许可证和架构边界内自主作出技术决定并留痕，不把实现细节变成业主必须猜答的技术选择题。是否请示按业务后果判断。

## AI 可自主执行

以下事项在当前闸门允许、且不触发后文红线时，由 AI 按最佳实践处理：

- 只读调查、文档整理、测试设计、风险分析和方案比较。
- 既定技术栈内的实现、重构、命名、文件组织、自动化和测试补充。
- 不改变产品范围、费用和风险等级的依赖选择；重大选择必须写 ADR。
- 契约、数据库迁移、CI/CD、工具链和工程护栏设计；必须可回滚、可验证并符合宪法。
- 修复缺陷、安全问题、测试隔离和性能问题，但不得借机改变用户行为或承诺。

## AI 自主决定但必须留痕

| 事项 | 留痕位置 |
|---|---|
| 重大框架、编辑器、渲染器、存储、同步或跨端方案 | ADR |
| 新增关键依赖、许可证例外、替代方案取舍 | ADR + 依赖清单 |
| 数据 schema、文件格式、模板 DSL、host 协议变更 | ADR + 版本/迁移说明 |
| 测试策略、性能预算、兼容矩阵的实质变更 | 对应规范 + ADR |
| 路线图顺序或并行方式的实质变更 | 路线图 + 重新审计记录 |

## 必须暂停并征得业主批准

| 类别 | 典型事项 |
|---|---|
| 费用 | 购买软件/域名/账号/证书/设备；启用付费 API；超过已批准预算或改变收费方式 |
| 产品范围与承诺 | 新增/删除目标用户、首战工作流、平台、核心功能；改变输出质量承诺或范围外清单 |
| 成功定义 | 修改成功指标、失败条件、实验样本、评分阈值或已预注册的判断口径 |
| 用户数据与隐私 | 将本地资料发送到新的第三方；改变保留/训练/遥测承诺；导出、迁移或批量处理真实用户数据 |
| 破坏性操作 | 删除/覆盖项目、数据库、备份、用户文件；不可逆迁移；使旧版本无法读取的数据格式变更 |
| 对外行为 | 发布网站/应用/包，提交商店，推送更新，发送消息，公开仓库或创建对外可见资源 |
| 法律与品牌 | 商标申请、协议/隐私政策承诺、引入许可证例外、使用权不明确的字体/素材/数据 |
| 凭证与身份 | 需要业主登录、实名、二次验证、签名证书、开发者账号或授予高权限 |

## 当前阶段的额外限制

项目尚处 G0：即使某项技术动作通常可由 AI 自主决定，也不得初始化工程、安装 DevEco Studio/SDK 或其他依赖、注册服务、创建远程仓库、写代码或产生费用。只有对应闸门明确通过后，权限才随阶段开放。

## 遇到不确定性时

- 技术不确定但业务后果不变：AI 调查、做可逆 PoC、选择最佳方案并写 ADR。
- 业务后果、费用、隐私或不可逆性不确定：先停止相关动作，向业主解释“会改变什么”，而不是要求业主判断底层技术。
- 紧急安全问题：先采取不破坏数据、可恢复的最小隔离措施，再报告；不得借紧急之名扩大权限。
