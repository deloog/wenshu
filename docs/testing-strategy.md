# 文枢测试与验证策略（G0）

> 状态：G0 已批准（2026-07-20）。工具名和命令在 G1 锁定；本文固定“什么必须被真实验证”。

## 1. 总原则

1. 测试名称与真实性相符；mock 核心依赖的测试不得称为集成或 E2E。
2. 行为、契约和缺陷测试先行；视觉探索可以先形成固定基准和人工判据，再自动化。
3. 同一 fixture 从单元规则、渲染集成、PDF 检查到 E2E 尽量贯通，避免各层讲不同故事。
4. 失败必须可诊断；日志、截图、PDF、页面图、trace、seed 和环境版本作为测试产物保存。
5. 关键质量以行为清单和门槛判断，不用单一覆盖率百分比替代。

## 2. 测试分层

| 层级 | 文枢中的对象 | 允许替代什么 | 不得替代什么 |
|---|---|---|---|
| 单元 | schema、模板规则、分页检查、ID、哈希、事务编译、权限判定 | 可 mock host/时钟/模型边界 | 不证明浏览器分页、数据库或真实模型质量 |
| 契约 | 文档 schema、模板 DSL、host 能力、模型工具、知识包版本 | 可使用固定样例 | 不证明具体平台实现 |
| 组件/渲染 | 编辑器节点、diff、页面组件、错误状态 | 可用内存文档 | 不冒充完整 PDF 或文件系统集成 |
| 集成 | Chromium 打印、字体加载、PDF 解析、本地数据库、文件导入导出、host 实现 | 第三方付费服务可用契约 fake | 被验证的浏览器、字体、数据库、文件系统不能 mock |
| E2E | 导入草稿 → 套模板 → 分页检查 → 修改 → 导出 → 重导入 | 非核心付费第三方可使用沙箱/fake | 核心入口、构建、事务、存储和导出不能拦截 |
| 专项评测 | PDF 视觉、AI 质量、性能、安全、崩溃恢复、跨端 | 依专项说明 | 不用演示成功代替固定样本和阈值 |

## 3. 数据库与文件系统真实性

- 若生产真源使用 SQLite，集成测试必须使用同 SQLite 版本/能力和真实迁移；内存 Map、JSON 文件或其他数据库不能替代。
- 若后续同步服务使用 PostgreSQL 等服务端数据库，其集成测试必须以容器/临时真实实例运行全部迁移。
- 每个并行 worker 使用独立数据库文件/schema、临时目录、项目 ID 和端口；路径必须解析到受控测试目录。
- 覆盖空库迁移、旧版升级、事务/并发、崩溃中断、重复导入、损坏文件、磁盘满/拒绝权限和恢复。
- 原始 fixture 只读；导入和转换写到临时副本，不得原地修改测试样本。
- 知识包必须在干净环境重新导入并比较真源对象、版本、引用、审计和附件；仅比较“文件存在”不合格。

## 4. PoC-A 排版验证

固定以下变量：

- 渲染器及完整版本（Chromium/Electron）
- 操作系统、缩放、DPI、纸张、页边距和打印参数
- 字体文件、版本、哈希、字重和 fallback
- 文档 fixture、模板版本、图片/表格资源
- 页面规则和允许容差

每次回归至少检查：

1. PDF 可解析、页数在预期范围、页面尺寸正确；
2. 正文文本未丢失、截断或重复；
3. 目录标题与页码一致；
4. 标题落页尾、孤行/寡行、表格跨页、图片越界/遮挡等 validator 结果；
5. 字体存在并按能力检查嵌入/替代；
6. 固定页面渲染为图片后做视觉差异，差异超阈值必须人工审查，不能自动更新基线；
7. 同一输入重复运行的页数、规则结果和关键几何信息一致。

视觉基线更新必须说明为什么变化、哪些页面变化并附审查；“新截图看起来也行”不是自动批准依据。

## 5. AI/非确定性验证

- 固定评测集覆盖结构识别、重写、引用、不可改项、不可猜测项、工具选择、拒绝越权和 prompt injection。
- prompt、模型、参数、工具 schema、评测日期、成本和结果版本化。
- 结构化输出必须 parse；工具调用先验权限；高风险动作停在人类确认前。
- 日常确定性测试使用录制响应/契约 fake；真实模型评测单独运行并有费用闸门。
- 模型结果使用明确 rubric 或成对比较，重复运行以观察波动；mock 通过不代表真实质量通过。
- 模型升级、prompt/工具变更或 provider 切换必须跑相同回归集。

## 6. E2E 关键闭环

Alpha 前至少覆盖：

- 新建/导入项目 → 结构化 → 应用模板 → 预览 → 导出 PDF
- 页面检查发现问题 → 定位 → 修正 → 检查清零/获准豁免
- AI 修改 → diff → accept/reject → undo/redo → 审计事件
- 保存 → 强制中断/重启 → 恢复 → 内容和历史一致
- 导出完整知识包 → 干净环境重导入 → 再导出
- 缺字体、无权限、磁盘不足、文件损坏、模型超时/限额的降级

## 7. 并行与 CI

- G1-11 的 8 个快速作业及本地/远程同构边界见 [并行 CI 基线](ci.md)；本地最多 4 路、远程 matrix 最多 8 路，不重试失败作业。
- lint、format、typecheck、单元、契约、构建、密钥和许可证扫描无依赖时并行。
- 集成/E2E 先按数据库、目录、端口、账号和额度隔离，再按包/浏览器/fixture 分片。
- 迁移 job 先于使用该数据库结构的测试；共享不可隔离资源时明确串行。
- 同分支新提交取消旧运行；缓存依赖于锁文件、运行时和平台版本。
- PR 快速门禁运行关键真库集成和关键 E2E；全 fixture、跨平台、性能和真实模型评测进入 main/定时/发布流水线。
- 为并行设置 CPU、内存、worker 和第三方速率上限；不靠无限并发换速度。

## 8. flaky 与完成证据

- 自动重试只用于收集诊断，不把重试后通过计为稳定通过。
- flaky 必须登记原因、负责人和修复任务；被隔离的测试不计入门禁覆盖。
- Bug 修复先有失败测试或固定复现步骤，再实现修复。
- 完成报告列出实际命令、通过/失败/跳过数量和产物路径；没有运行的测试明确补验时点。

## 9. 文件体量

- 手写生产代码：达到 300 行预警，超过 400 行失败。
- 手写测试代码：达到 300 行预警，超过 500 行失败。
- 测试按行为/场景族/层级拆分；共享 fixture 只在确有复用时提取，不能让单个测试意图散落多处。
