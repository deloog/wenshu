## 0. 更正记录（2026-09-16 业主复核裁定）

本文初版（`804f0e1`）结论 2「成本不在打哪几页，在整份 30 页 DOM 的 print-layout，
与窗宽弱相关」**被 VM 数据直接推翻，现予更正**：

- 业主复算（实施者已独立复算确认，见 §2.2）：窗宽两点线性分解——2 页窗
  n=30 均值 1510.4ms、3 页窗 n=10 均值 2011.3ms ⇒ **固定成本 ≈509ms +
  边际成本 ≈501ms/页**；2 页窗的 1510ms 中 ~66% 随窗宽走，初版归因不成立。
- 初版赖以立论的本机地板探针（~60–90ms）两项缺陷如实登记：(a) 初版提交时
  无留证（脚本与产物均未入仓，不可复现——现已补 `scripts/a04e2b-print-floor-probe.ts`
  + 输出 `tmp/a04e-2b-probe/print-floor-output.txt`）；(b) 与 VM 隐含固定成本
  矛盾（6–8 倍）且同组读数自相矛盾（2 页窗 734.9 vs 6 页窗 116.5，暖化方差）——
  **本机地板读数不得用于任何归因承重**，归因权威口径=VM 批次内窗宽分解。
- P1 初版判「量级小」错误（固定成本占预算 51%）；P2 收益初版被高估。
  更正后路径排序见 §3/§4；**P7（首窗自适应放宽）为业主提出并登记**。

## 1. 结论摘要

1. 超限是**结构性**的：每次增量更新 VM 均值 2694ms = ranged print 1636ms/轮
   + navigate 432ms + compose/post <60ms。分解后**固定成本 ~509ms（print）+
   ~432ms（navigate）≈ 941ms——一页未打已到 1s 边缘**，≤1s 在「CDP
   printToPdf = 每编辑一次」架构内不可达，且比初版论证更硬。
2. print 成本**强相关于窗宽**（边际 ~501ms/页）：多打一页 +500.9ms（+33%），
   且 3 页窗样本全部是 zone-2 级联的第二轮（同编辑内更热），本应更快却贵
   500ms——对比比表面更强。
3. 可达 1s 的路径只有改变预览层级语义（§3 P4，涉预算语义裁定，业主已裁定
   走法见 §6）；大幅压缩 print 输入体量（§3 P2）破坏④等价性，否决。
4. 取消结案 3.7–4.1s 超 2s 是可修工程问题（§3 P6，业主已授权独立成棒）。
5. **实测数据最大单一杠杆是 P7**（首窗自适应放宽一页）：zone-2 级联率
   10/10，首窗直打 13-15 一轮 ~2011ms vs 两轮 3800ms，zone-2 均值
   4273→~2484ms，整体 p95 4370.7→**~2.5s**；与哨兵设计同源（ADR-0033 D2
   本来就多打一页哨兵），等价性论证不变，不碰红线。

## 3. 加速路径逐项

### P1 压 print 固定成本（~509ms，占预算 51%） —— 初版误判，更正为「主攻方向之一但暂无可攻击面」

初版以本机地板 60–90ms 判其「量级小」，错误（业主裁定更正）。固定成本
~509ms 的构成（调用装配/字体子集/整份布局初始化）未经 VM 四联探针分解前
不能断言可压空间；已知机制事实：字体子集每次调用重做、不可跨调用缓存。
**判定：量级大、暂无可攻击面，待 §5 VM 探针分解后再评。**

### P2 窗级 DOM 打印 —— 保真等价被破坏，否决（收益初版高估一并更正）

把窗页+哨兵组成独立小 DOM：按 §2.2 分解，省的是固定成本中的布局分量，
2 页窗 print 乐观估计仍 ~1.0–1.2s（小固定+2×501 边际），**即便不考虑保真
问题也救不了预算**（初版「降到 200–400ms」高估，更正）。且窗级 DOM 从窗
起点重排，跨窗界段落/表格行位置不再逐 run 等价于整份重渲（④失守）。
**判定：与 ADR-0033 等价性红线冲突，否决。**

### P3 DOM 增量补丁免整页导航 —— 省 ~332–500ms，保守可行但救不了预算

navigate 432–552ms → 就地补丁（Chromium 增量重排），预期 50–150ms。
总耗时 ~2.2–2.4s，p95 仍 ~2.5–4s。补丁正确性须机械论证（补丁后 DOM 渲染
结果 ≡ 重组装 DOM）。可作组成优化，单独不构成解法。

### P4 双层预览（即时 HTML 层 + 异步 PDF 精确层） —— 架构上唯一可达 1s，但「重新解释预算」已被业主裁定否决；正路见 §6

初版提议把「≤1s」重解释为层 1 交互反馈。业主裁定（2026-09-16）：**否决
「重新解释」这个动作，不是否 P4 架构**——G0 预算对象原文「相关页面更新」、
任务书 §4.1 不得放宽任何预算、宪法 §18 禁止修改验收口径制造完成；先测出
4370.7ms 再改对象正是 §18 要防的形态；且层 1 HTML 预览不含真实分页（真实
分页正是 print-layout 算出的），不构成「页面更新」，是实打实的重定义。
**P4 架构本身与冻结 UX 契约兼容**（G0 失败处理列「允许显示正在重新分页，
旧预览不消失」、ux-state `stalePreviewRetained: const true`），其正名之路
是 G0 级预算修订（§6），不是重解释。

### P5 打印调用合并/防抖 —— 工程标配，不改单次量级

连续击键合并（debounce ~300ms）减少调用次数，不改单次延迟。任何方案叠加。

### P6 取消结案 3.7–4.1s → 每任务独立 target —— 业主已授权，**独立成棒**，不并 2c

当前 abort 在阶段边界生效、在途 printToPdf 跑完才结案（VM ~3.7s）。改为
后台整份在同会话**独立 target** 执行，取消=`Target.closeTarget`（预期
<100–300ms），会话本体不污染、可立即复用；对 run-01 冷启离群 266.7s 同类
风险免疫。业主裁定（2026-09-16）：**单独成棒、验收就一条 2s**，不并入 2c——
2c 形态取决于 Q1 流程周期，P6 现在不阻塞；并入还会毁掉归因性（取消改善
说不清是谁的功劳）。

### P7 首窗自适应放宽一页（业主提出，2026-09-16 登记） —— 实测数据最大单一杠杆，不碰等价性红线

zone-2 级联率实测 10/10（13-14 → 13-15，两轮 1740+2060=3800ms）。若首窗
自适应放宽一页（直打 13-15）：一轮 ~2011ms，省 ~1789ms；zone-2 均值
4273→~2484ms；**整体 p95 4370.7→~2.5s**。机制与 ADR-0033 D2 哨兵设计
同源（本来就多打一页哨兵），只是把初始窗开大一格，等价性论证不变。
单页边际 501ms vs 重打一轮 2011ms ⇒ **级联概率 >~25% 即正收益**（zone-2
实测 100%）。自适应策略候选：静态 +1 页 / 按块类型（节尾段落后必接新页
内容时放宽）/ 按历史级联率——2c 设计时定。**仍然到不了 1s**，但应进 2c
方案表，且让 G0 修订论证「PDF 精确层要多慢」时用 ~2.5s 而非 2–3s。

## 4. 组合判断（更正后）

## 5. 开放测量点与跟进登记

1. **VM 侧 print 地板四联探针**（极简 1 页 / CJK 1 页 / 30 页 DOM ranged
   2 页 / 全量）：把 ~509ms 固定成本分解为「调用装配 vs 整份布局」，
   决定 P1 有无攻击面。成本：一次 ~10 分钟 VM 探针批次，非全门批次。
2. **run-01 取消结案 266.7s 冷启离群**：机理未解释（疑似会话首个整份打印+
   批初宿主负载叠加），登记复现探针；P6 closeTarget 形态对其免疫。
3. P3 若采纳：补丁后 DOM 与重组装 DOM 渲染等价性须机械论证（同 ④口径）。
