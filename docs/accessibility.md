# 文枢无障碍基线（G0）

> 目标：Web 与桌面核心工作流以 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) AA 为基线；桌面壳和 ArkWeb 在平台可用能力范围内保持一致语义。自动检查不能代替键盘和读屏人工验证。

## 必须满足

- 全流程可仅用键盘完成；焦点顺序符合视觉和任务顺序。
- 焦点清晰可见且不被浮层遮挡；打开对话框后焦点进入，关闭后返回触发点。
- 编辑器、页面预览、问题列表、AI diff 和引用区域有明确名称、角色和状态。
- 颜色不作为问题级别、接受/拒绝、增删 diff 或保存状态的唯一信号。
- 文本和关键控件达到 AA 对比度；支持至少 200% 界面缩放而不丢失核心功能。
- 可调整字号；界面放大不改变导出 PDF 的模板物理尺寸，二者设置分离。
- 拖拽/移动节点必须提供键盘或菜单等非拖拽替代。
- 动画尊重减少动态效果；无闪烁和不必要连续动画。
- 错误信息与相关字段/操作关联，读屏可感知但不反复抢焦点。
- 长任务进度、完成、失败和取消结果通过可访问状态区域表达。

## 文档编辑专项

- 标题、列表、表格、图片说明和引用保持语义结构，不只依赖视觉样式。
- 表格提供表头关系；复杂表格超出首战范围时应明确降级，而非生成不可访问结构。
- AI diff 对增、删、改提供文本标签和逐项导航；不能只用红绿颜色。
- 页面问题可从列表跳到对应节点，并提供返回路径。
- 图片插入流程提供替代文本字段；装饰性图片可明确标记。

## 验证

- 自动：语义、名称、对比度、常见 ARIA 和键盘陷阱扫描。
- 人工：仅键盘完成关键 E2E；至少一种 Windows 读屏组合；200% 缩放；高对比/减少动态效果。
- 跨壳：Electron 和 ArkWeb 的焦点、快捷键和读屏能力分别记录，不因 Web 通过而自动判定壳层通过。
