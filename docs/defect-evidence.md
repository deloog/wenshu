# 缺陷证据标准（G2-01）

> 用途：任何缺陷（含审计发现）从发现到关闭的证据链。先有可重复失败证据，再有修复；不允许"改了再说"。来源：G2-01（R-TEST/R-SEC）。

## 1. 发现（报告必须包含）

- 现象与期望行为的精确描述；受影响的任务 ID 与文件/守卫位置。
- **最小可重复步骤**：输入、环境、命令； flaky 场景附随机 seed 与出现率。
- 证据附件：日志、截图、trace，存于受控目录（`test-results/` 或审计报告内引用）。

## 2. 定级

- BLOCKER（安全/数据/门禁失效）、MAJOR（验收不成立）、MINOR（质量缺口）、NOTE（观察/限制）。定级理由写明；实施者可异议但不得改级。

## 3. 修复前

- 缺陷已被转化为**可重复失败的自动化测试**（或明确写明为何只能人工复核及复核步骤）。
- 该测试在修复前必须真实失败（红），且失败原因与缺陷一致——不是无关红。

## 4. 修复与关闭

- 修复只针对根因，不夹带无关变更；回归测试变绿且守卫变异仍被覆盖。
- 关闭权属于原发现/审计角色的复审；实施者不得自行关闭。
- 关闭记录引用：失败证据、修复提交、复审结论。

## 反例（不成立的"已修复"）

- 没有失败证据、只有"我这边好了"。
- 先改代码再补一个从来不红的"回归测试"。
- 通过删除/放宽触发条件让缺陷不再出现（如把校验改松）。
- 实施者自我复审关闭自己修的问题。
