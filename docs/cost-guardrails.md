# 文枢成本护栏（G0）

> 状态：G0 已批准（2026-07-20）。未取得业主明确批准前，项目新增现金支出上限为 **0 元**；现有个人订阅也不得被 AI 假定为可自动消费的项目资源。

## 1. 当前阶段策略

- G0/GR：只做文档、只读调研和本地材料，不注册付费服务、不购买软件/域名/账号。
- PoC-A：优先完全确定性的本地渲染，不依赖付费模型；AI 修正步骤可以先用人工/固定规则模拟验证闭环。
- PoC-B：BYOK 优先。真实模型评测必须先登记 provider、模型、单次上限、样本数量和最大总成本，并获得批准。
- Alpha：任何项目托管额度、内置 AI 额度、同步或遥测服务需单独预算，不从技术选择中自动产生。

## 2. 付费调用前置控制

每个付费 provider 适配器必须在发出请求前依次通过：

1. 功能/管理员 kill switch；
2. 用户授权与 provider 选择；
3. 单请求输入/输出与附件大小上限；
4. 单任务、单日和项目总预算；
5. 并发与速率限制；
6. 超时、取消和有限重试预算；
7. 缓存/复用检查；
8. 超限后的明确降级，而不是继续扣费。

## 3. 成本记录

- 记录 provider、模型、计量单位、估算/实际用量、延迟、是否缓存和任务 ID；默认不记录完整正文。
- 价格配置版本化并标明更新时间；价格不写死在业务逻辑中。
- 评测报告同时报告质量、延迟和成本，不以模型“更聪明”忽略单位经济性。
- CI 中真实付费测试默认关闭；专门工作流需手动批准、并发 1、硬额度和清晰账单标签。

## 4. 需要业主批准

- 任意新增现金支出、付费档升级、域名/证书/开发者账号/设备购买。
- 提高任何已批准的单次、单日或总预算。
- 从 BYOK 改为项目代付，或改变用户可见的计费/免费承诺。
- 为降低费用而改变隐私、模型训练或数据使用承诺。

具体金额在进入真实付费评测或采购前追加到决策记录；没有金额不代表无限预算，而代表不得消费。
