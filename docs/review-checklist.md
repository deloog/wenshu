# 评审清单（G2-01）

> 用途：功能任务 PR 的评审（含独立审计前的实施者互审与审计者的快速定位）。评审不替代独立审计；缺任一项即退回。来源：G2-01（R-TEST/R-SEC）。

## A. 身份与边界

- [ ] 任务 ID 真实存在于 GR 路线图，DoR 在开工时满足（依赖任务均已 ✅ 签署）。
- [ ] 变更文件清单与任务书"范围内/范围外"一致；无无关文件、无夹带重构。
- [ ] 冻结纲领、宪法、决策记录、验收标准、生成物、lockfile 未被手工改写。
- [ ] `AGENTS.md` 未新增任务状态、DoR 放行或完成宣称。任务状态的唯一权威来源是[路线图 §3.1 执行台账](implementation-roadmap.md)（由 `G2-04` 门禁守护）；需要变更状态就改台账，不改 `AGENTS.md`。

## B. 真实验证

- [ ] 每个验收标准映射到具体测试/证据；测试层级标注正确且能被层级审计发现。
- [ ] 抽查至少一个核心守卫做变异：守卫被削弱/删除时对应测试应变红。
- [ ] 无 flaky 靠重试变绿；失败证据保留。
- [ ] 日志/诊断不含秘密、原始输入值、绝对敏感路径。

## C. 工程质量

- [ ] 零显式/隐式 `any`、零 `@ts-ignore`/`eslint-disable`；不可信输入从 `unknown` 收窄。
- [ ] 文件体量护栏内；拆分按职责而非机械切片。
- [ ] 新依赖已声明且经供应链基线（许可/SBOM/漏洞）。

## D. 诚实性

- [ ] 完成声明列出的检查与日志一致；未执行项写明原因与补验时点。
- [ ] 已知限制、NOTE 级问题如实登记，无"已解决"冒充。
- [ ] 实施记录、台账、审计任务书三处状态一致。
